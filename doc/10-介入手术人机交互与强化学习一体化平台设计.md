## 一、设计目标与核心理念

### 1.1 问题陈述

介入手术仿真系统有两个截然不同的使用场景，但底层需求高度重叠：

| 场景 | 核心需求 | 当前状态 |
|---|---|---|
| **人机交互**（HCI） | 医生/操作员通过键盘、手柄、点击导航实时操控导丝，60Hz 跟手，可视化反馈 | ✅ 已有 Godot + WebSocket + FastAPI 链路 |
| **强化学习训练**（RL） | 策略网络通过 Gym API 与仿真环境交互，批量采样、reward 反馈、收敛到达 | ⚠️ 已有 `src/cathsim/gym/`，但绑 dm_control/MuJoCo，未接 Newton/ShapeIntent |

两者共享的底层能力：

- **物理仿真**：Newton XPBD 导丝 + SDF 血管碰撞（doc/08）
- **控制抽象**：ShapeIntent → Controller → `push/rotate`（doc/09）
- **导航编排**：NavigationEngine（progress / deviation / curvature / risk / safety）
- **路径规划**：PathPlanner（A* / 图搜索 / B-spline 平滑）
- **血管资产**：STL 网格、中心线、SDF、routes.json

### 1.2 核心理念：一体化平台，双模式运行

```text
┌─────────────────────────────────────────────────────────────────┐
│                    一体化平台 (Unified Platform)                   │
│                                                                   │
│  ┌──────────────┐                          ┌──────────────────┐  │
│  │  HCI 模式     │                          │  RL 训练模式      │  │
│  │  (交互入口)   │                          │  (训练入口)       │  │
│  │              │                          │                  │  │
│  │  Godot 前端   │                          │  Gymnasium Env   │  │
│  │  WebSocket    │                          │  SB3 PPO/SAC     │  │
│  │  FastAPI      │                          │  TensorBoard     │  │
│  │  Session Mgr  │                          │  回放/评分       │  │
│  └──────┬───────┘                          └────────┬─────────┘  │
│         │                                            │             │
│         ▼                                            ▼             │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │              共享核心 (Shared Core)                          │ │
│  │                                                             │ │
│  │  ShapeIntentController  ←  Human UI = RL Policy 共用         │ │
│  │         │                                                   │ │
│  │         ▼                                                   │ │
│  │  NavigationEngine (编排: progress/deviation/curvature/risk)  │ │
│  │         │                                                   │ │
│  │         ▼                                                   │ │
│  │  PhysicsEngine (NewtonEngine: XPBD 导丝 + SDF 碰撞)          │ │
│  │         │                                                   │ │
│  │         ▼                                                   │ │
│  │  PathPlanner (A* / 图搜索 / B-spline 平滑)                   │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

**"一体化"**的含义：

1. **同一套物理引擎**——HCI 和 RL 跑的是同一个 `NewtonEngine`，导丝行为完全一致。RL 学到的策略在 HCI 模式下可直接使用，不存在 sim-to-sim gap。
2. **同一套控制抽象**——人和策略都下达 `ShapeIntent`，由同一个 `ShapeIntentController` 解算成 `push/rotate`。策略不需要学习底层电机控制，只需学习高层导航意图。
3. **同一套导航状态**——`NavigationState`（progress / deviation / curvature / risk / safety）是两种模式的共用状态表示，RL 的 observation 与 HCI 的 HUD 显示源自同一数据源。
4. **同一套血管资产**——STL/SDF/中心线/routes.json 在两种模式间共享，切换 phantom/route 即可。

**"双模式"**的含义：

| 维度 | HCI 模式 | RL 训练模式 |
|---|---|---|
| 入口 | Godot 客户端 → WebSocket → FastAPI | Python 进程内 `gym.Env` |
| 渲染 | Godot 3D 实时渲染 (60fps) | 无渲染（headless）或可选 rgb_array |
| 控制来源 | 键盘/手柄/点击 → ShapeIntent | 策略网络 → ShapeIntent |
| 步频 | 25–60 Hz（实时跟手） | 无限制（物理引擎步频上限） |
| 生命周期 | Session 管理（长连接） | Episode 循环（reset/step/done） |
| 并行 | 单 session / 连接 | 多进程 env（近期）/ Isaac Lab 千环境（远期） |
| 输出 | 实时可视化 + 状态流 | 模型权重 + 训练曲线 + 回放轨迹 |

### 1.3 设计原则

1. **共享核心零分叉**：`NavigationEngine` + `ShapeIntentController` + `PhysicsEngine` 不因模式不同而走不同代码路径。模式差异只体现在**入口层**（谁产生 ShapeIntent）和**出口层**（状态给谁消费）。
2. **接口对齐 Isaac Lab**：RL env 的 `obs/action/reward` 契约与 Isaac Lab 一致（doc/09 §七），将来提升进 Isaac Lab 不改训练代码。
3. **物理与渲染解耦**：物理始终是 Newton（doc/08 §3.4），渲染端可插拔。HCI 用 Godot，RL 用 headless，将来 RTX 是"再加一个渲染端"。
4. **模式显式化**：API/HUD 明确区分 `guided`（运动学演示）/ `physics`（物理仿真）/ `rl`（策略推理）三种保真度，不可混用（doc/05 §27.5）。

## 二、共享核心架构

### 2.1 分层总览

```text
        ┌─────────────────────────────────────────────────┐
  Human │ Godot: 键盘 / 点击 / 手柄 → ShapeIntent          │   ← HCI 入口
  RL    │ Policy Network → ShapeIntent                     │   ← RL 入口
        └───────────────────┬─────────────────────────────┘
                            ▼
        ┌─────────────────────────────────────────────────┐
        │ ShapeIntentController                            │  ← 控制抽象层
        │  (PhysicsAutopilot 泛化: look-ahead + J-tip     │
        │   爬山 + 力门控 + stall 恢复 → push/rotate)      │
        └───────────────────┬─────────────────────────────┘
                            ▼  push, rotate ∈ [-1,1]²
        ┌─────────────────────────────────────────────────┐
        │ NavigationEngine                                 │  ← 编排层
        │  (progress/deviation/curvature/risk/safety)     │
        │  组装 NavigationState → RL obs / HCI 状态流      │
        └───────────────────┬─────────────────────────────┘
                            ▼
        ┌─────────────────────────────────────────────────┐
        │ PhysicsEngine                                    │  ← 物理层
        │  (NewtonEngine: XPBD 杆 + SDF 碰撞, 60Hz)        │
        └───────────────────┬─────────────────────────────┘
                            │
              ┌─────────────┼──────────────┐
              ▼             ▼              ▼
         SDF 碰撞场     中心线/路径     血管 mesh/STL
       (seg.nrrd)    (centerline.json)  (visual.stl)
```

### 2.2 核心模块（已有，本文不新增）

| 模块 | 文件 | 职责 | 双模共用点 |
|---|---|---|---|
| `ShapeIntent` | `services/shape_intent.py` | 高层命令数据模型（target_direction / target_waypoint / intensity） | Human 点击/手柄和 RL policy 输出都构造此对象 |
| `ShapeIntentController` | `services/shape_intent.py` | 将 ShapeIntent 解算为 `(push, rotate)` | 两种模式调用同一 `compute()` 方法 |
| `PhysicsAutopilot` | `services/physics_autopilot.py` | Controller 的底层控制律（look-ahead / J-tip 爬山 / 力门控 / stall） | 不直接暴露给模式层 |
| `NavigationEngine` | `services/navigation_engine.py` | 编排：持有 engine + path，派生 progress/deviation/curvature/risk/safety | 两种模式的核心编排器 |
| `NavigationState` | `services/navigation_engine.py` | 标准化状态表示（双模共用的数据结构） | RL obs 和 HCI HUD 的共同数据源 |
| `PhysicsEngine` (协议) | `services/physics/base.py` | `reset() / step(push,rotate) / render_bodies() / control_timestep` | 双模调用的同一接口 |
| `NewtonEngine` | `services/physics/newton_engine.py` | Newton XPBD 实现 | 双模的物理后端 |
| `PathPlanner` | `services/path_planner.py` | A* 图搜索 + B-spline 平滑 | 双模的路径来源 |
| `PlannedPath` | `services/physics/base.py` | 弧长几何（progress/deviation 投影） | 双模的路径表示 |

### 2.3 共享数据流

两种模式的**核心数据流完全相同**，差异只在头尾：

```text
[输入]                          [核心处理]                        [输出]
─────────                      ──────────                       ─────────
Human:                    ┌──→ ShapeIntentController.compute() ──→┐
  键盘 → push/rotate      │    (intent, tip_pos, tip_dir, force)  │
  点击 → target_waypoint  │         ↓ push, rotate                │
  手柄 → target_direction │    NavigationEngine.step(push,rotate) │
                          │         ↓                              │
RL:                       │    PhysicsEngine.step(push, rotate)   │
  policy → ShapeIntent ───┘         ↓ RawPose                     │
                                    NavigationState                │
                          ┌─────────┬──────────────────────────────┘
                          │         │
                    HCI:  │    RL:  │
                    WebSocket    gym.step() return
                    Godot渲染     (obs, reward, done, info)
```

### 3.2 交互方式与 ShapeIntent 映射

| 交互方式 | 前端信号 | 后端处理 | ShapeIntent |
|---|---|---|---|
| **键盘 W/S/A/D** | `control(push, rotate)` | 直接 `NavigationEngine.step(push, rotate)` | 不经过 ShapeIntent（直通模式） |
| **左键点击导航** | `navigate_click(screen_pos)` | 投影到 centerline → `target_waypoint` → `ShapeIntent` | `target_waypoint = 投影点` |
| **ESC 解除自动** | `autopilot_off` | `set_shape_intent(None, active=False)` | 退回手动 |
| **手柄摇杆**（未来） | 摇杆方向 → `target_direction` | `ShapeIntent` | `target_direction = 摇杆向量` |
| **形变滑块** | `engine_params` | `NavigationEngine.set_engine_params()` | 物理参数实时调（domain randomization 入口） |
| **分支切换 B** | `branch_cycle` | `select_route(target)` | 切换 planned_path |

### 3.3 实时链路（已有，引擎无关）

复用 doc/07 阶段 B 的实时链路，零改写：

- `PhysicsWorker`：后台线程 `while running: engine.step(latest_input)`，自主步进 + 双缓冲发布 `Frame`。
- `websocket_handler.py`：25Hz sender + `control` 只覆盖 `latest_input`（不排队）。
- `state_batch` 协议：`bodies[].pos/quat`（导丝渲染）+ `path.waypoints`（路径）+ `tip`（尖端）+ `seq/t_phys`（时序）。
- Newton 60Hz 后，可缩短/关闭 `guidewire_renderer.gd` 的插值时长。

### 3.4 会话管理

复用 `SessionManager`（`services/session_manager.py`），支持多并发 session：

- `create_session(phantom, target, planned_path, guided, route_target)` → `(session_id, NavigationState)`
- `step(session_id, push, rotate)` → `NavigationState`
- `reset_session(session_id)` → `NavigationState`
- `close_session(session_id)`
- 自动超时清理（默认 1 小时）

### 3.5 前端面板设计

借鉴 VPP README §2（术中导航界面目标）的"主操作区 + 辅助导航区 + 顶部控制状态层 + 底部状态栏"四区布局理念，适配 cathsim 的 Godot CanvasLayer / Control 架构。VPP 面向术中 DSA/X-ray 影像导航，cathsim 面向仿真训练与 RL 推理验证，两者共享后端但前端渲染技术不同（Godot vs PyQt5+PyVista），布局原则可复用。

#### 4.2.1 新增 `NavigationGymEnv`

        domain_randomization: bool = False,

#### 4.2.2 Observation（全部来自 NavigationEngine / NavigationState）

```text
obs = {
    "tip_position":     (3,)    float32   # NavigationState.tip_position
    "tip_direction":    (3,)    float32   # NavigationState.tip_direction
    "progress":         (1,)    float32   # NavigationState.path_progress [0,1]
    "deviation":        (1,)    float32   # NavigationState.path_deviation (m)
    "local_tangent":    (3,)    float32   # PlannedPath.tangent_at_arclen
    "contact_force":    (1,)    float32   # NavigationState.contact_force
    "wall_distance":    (1,)    float32   # NavigationState.wall_distance
    "curvature":        (1,)    float32   # NavigationState.curvature
    "risk_score":       (1,)    float32   # NavigationState.risk_score
}
# 历史堆叠可通过 TransformDictObservation 自定义: obs(t), obs(t-1), obs(t-2)
```

#### 4.2.3 Action（= ShapeIntent，由 Controller 落地为 push/rotate）

| 模式 | action 维度 | 语义 | Controller 行为 |
|---|---|---|---|
| `shape_intent`（推荐） | (4,) | `[desired_direction(3), intensity(1)]` | Controller 用 direction 作 aim override |
| `direct`（baseline） | (2,) | `[push, rotate]` | 绕过 Controller，直通 `engine.step()` |
| `waypoint`（高级） | (3,) | `[waypoint_offset(3)]` | Controller 用 waypoint 作 aim override |

```python
def step(self, action):
    if self.action_mode == "shape_intent":
        intent = ShapeIntent(
            target_direction=action[:3],
            intensity=action[3],
        )
        push, rotate = self.controller.compute(
            intent, tip_pos, tip_dir, contact_force
        )
    elif self.action_mode == "direct":
        push, rotate = action[0], action[1]
    ...
    state = self.engine.step(push, rotate)
    ...
```

#### 4.2.4 Reward（对齐 doc/09 §6.3，基于 centerline progress）

```text
R = w_p · Δprogress                  # 主项：沿中心线弧长增量
  + w_a · dot(tip_dir, tangent)      # 对齐奖励
  − w_c · ||contact_force||²         # 接触/穿壁惩罚
  − w_r · risk_score                 # 风险惩罚
  + R_reach (到达目标 +1)             # 到达奖励
  − R_fail (穿壁/超时 −1)             # 失败惩罚
```

权重作为 env 构造参数，支持 curriculum 阶段调整。

#### 4.2.5 Reset 随机化 + Curriculum

```text
reset 随机化 (domain_randomization=True):
  - 起点 s0 扰动 (±5mm)
  - 摩擦系数 μ (0.8x–1.2x)
  - SDF/半径噪声 (±10%)
  - 初始 J-tip 角度 (±15°)
  - 通过 engine_params 通道注入

curriculum (route 天然分级):
  Stage 0  直短路径    endpoint_0    (aorta_tree 最短分支)
  Stage 1  单弯路径    endpoint_9
  Stage 2  锐弯路径    endpoint_3

```

### 4.3 训练管线

#### 4.3.1 SB3 集成（复用现有 `src/cathsim/rl/`）

```python
# 训练入口 (扩展现有 src/cathsim/rl/train.py)
from stable_baselines3 import PPO
from cathsim.gym.envs.navigation import NavigationGymEnv
from cathsim.gym.wrappers import SingleDict2Array, TransformDictObservation

def make_train_env(phantom, route_target, stage):
    env = NavigationGymEnv(
        phantom=phantom,
        route_target=route_target,
        curriculum_stage=stage,
        domain_randomization=True,
    )
    env = SingleDict2Array(env)                    # obs 向量化
    env = TransformDictObservation(env, ...)        # obs 变换/堆叠
    return env

model = PPO("MultiInputPolicy", env, verbose=1, tensorboard_log="./logs")
model.learn(total_timesteps=600_000)
model.save("./models/nav_ppo_endpoint_0")
```

#### 4.3.2 策略推理 → HCI 模式无缝切换

训练好的策略可直接加载到 HCI 模式作为"AI 辅助驾驶"：

```python
# HCI 模式下的策略推理 (FastAPI 侧)
model = PPO.load("./models/nav_ppo_endpoint_0")
# 从上一步 NavigationState 构建 obs（与 RL env 的 _state_to_obs 一致）
state = navigation_engine.reset()  # 或持有上一步的 state
obs = _state_to_obs(state)         # 与 NavigationGymEnv._state_to_obs 相同

# 策略输出 ShapeIntent → Controller → push/rotate
action, _ = model.predict(obs)
intent = ShapeIntent(target_direction=action[:3], intensity=action[3])
push, rotate = controller.compute(intent, state.tip_position, state.tip_direction,
                                  state.contact_force)
state = navigation_engine.step(push, rotate)
```

这就是"一体化"的核心价值：**RL 训练的策略在 HCI 模式下零适配即可运行**，因为底层 engine/controller/state 完全相同。

### 4.4 并行与 Isaac Lab 提升（诚实边界）

- **近期**：单环境 = 单 Newton session + 每步 numpy 同步。并行靠多进程（`SubprocVecEnv`），不是千环境。
- **千环境并行**属 doc/08 §3.4 的提升通道：Newton 场景 → `make_instanceable` + 批量 Warp kernel → Isaac Lab。触发点：RL 训练成为现行目标时启动。
- 本文保证**接口就绪**：Gym env 契约与 Isaac Lab 一致，将来换底座不改训练代码。

## 六、模式切换与保真度显式化

### 6.1 三种保真度模式

| 模式 | 引擎 | 控制方式 | 保真度 | 用途 |
|---|---|---|---|---|
| `guided` | `KinematicEngine` | 运动学覆写（沿中心线） | 低 | 演示/可达性验证/路径可视化 |
| `physics` | `NewtonEngine` | 力驱动 + ShapeIntentController | 高 | 人机交互 / RL 训练 / 策略推理 |
| `rl` | `NewtonEngine` | 策略网络 → ShapeIntent | 高 | AI 辅助驾驶（策略加载到 HCI） |

### 6.2 模式标识传播

```text
session_start → mode: "guided" | "physics" | "rl"
  ├─ HUD 显示当前模式
  ├─ state_batch 携带 mode 字段
  └─ API 拒绝跨模式混用（如 guided session 不能发 shape_intent）
```

### 6.3 RL 策略 → HCI 的加载流程

```text
1. 训练: RL 模式下训练 → 保存 model.zip
2. 加载: HCI session_start 时指定 policy_path
3. 推理: 每步 policy.predict(obs) → ShapeIntent → Controller → push/rotate
4. HUD 标注 "RL AI 辅助" 模式
5. ESC 随时切回手动
```

### 9.2 T0 详细：NavigationGymEnv 骨架

**新增文件**：`src/cathsim/gym/envs/navigation.py`

```python
class NavigationGymEnv(gym.Env):
    metadata = {"render_modes": ["rgb_array", None], "render_fps": 60}

    def __init__(self, phantom, route_target, action_mode="shape_intent",
                 max_episode_steps=300, curriculum_stage=0,
                 domain_randomization=False):
        # 构造 NavigationEngine (含 NewtonEngine + ShapeIntentController)
        self.engine = NavigationEngine(
            phantom=phantom,
            route_target=route_target,
            guided=False,          # 物理模式
        )
        # 确保 ShapeIntentController 已构造（NavigationEngine 中懒加载）
        if self.engine._controller is None:
            self.engine._ensure_controller()
        self.controller = self.engine._controller
        self.action_mode = action_mode
        self.max_episode_steps = max_episode_steps
        self._step_count = 0
        self._last_state = None     # 上一步 NavigationState
        self._prev_progress = 0.0   # 用于 reward 的 Δprogress
        ...

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)
        state = self.engine.reset()
        self._step_count = 0
        self._last_state = state
        self._prev_progress = state.path_progress
        return self._state_to_obs(state), {}

    def step(self, action):
        # action → ShapeIntent → Controller → push/rotate
        push, rotate = self._resolve_action(action, self._last_state)
        state = self.engine.step(push, rotate)
        reward = self._compute_reward(state)
        terminated = state.done
        truncated = self._step_count >= self.max_episode_steps
        self._last_state = state
        self._step_count += 1
        return self._state_to_obs(state), reward, terminated, truncated, {}

    def _resolve_action(self, action, state):
        if self.action_mode == "shape_intent":
            intent = ShapeIntent(
                target_direction=action[:3],
                intensity=float(action[3]),
            )
            return self.controller.compute(
                intent, state.tip_position, state.tip_direction,
                state.contact_force,
            )
        elif self.action_mode == "direct":
            return float(action[0]), float(action[1])
        ...

    def _compute_reward(self, state):
        # R = w_p·Δprogress + w_a·alignment - w_c·contact² - w_r·risk + R_reach
        delta_progress = state.path_progress - self._prev_progress
        self._prev_progress = state.path_progress
        ...

    def _state_to_obs(self, state):
        return {
            "tip_position": np.array(state.tip_position, dtype=np.float32),
            "tip_direction": np.array(state.tip_direction, dtype=np.float32),
            "progress": np.array([state.path_progress], dtype=np.float32),
            "deviation": np.array([state.path_deviation], dtype=np.float32),
            "contact_force": np.array([state.contact_force], dtype=np.float32),
            "wall_distance": np.array([state.wall_distance], dtype=np.float32),
            "curvature": np.array([state.curvature], dtype=np.float32),
            "risk_score": np.array([state.risk_score], dtype=np.float32),
            ...
        }
```

## 十一、风险与回退

| 风险 | 应对 |
|---|---|
| Newton API 不稳导致 RL env 频繁改 | env 层只依赖 `PhysicsEngine` 协议，不直接调 Newton API |
| RL 训练不收敛 | 从 `direct` action mode（push/rotate 直通）起步，再切 `shape_intent` |
| 策略在 HCI 模式下行为异常 | ESC 随时切回手动；policy 推理与训练共用同一 controller/engine |
| 多进程并行 GPU 显存不足 | 近期单环境训练；大批量上 A6000 服务器或 Isaac Lab |
| VPP 桌面工作站与 Godot 前端分裂 | 后端服务层（FastAPI + NavigationEngine）严格共享，前端各自演进 |

---

## 十二、关键结论

1. **一体化平台 = 共享核心 + 双模入口**。共享核心是 `NavigationEngine + ShapeIntentController + PhysicsEngine + PathPlanner`；双模入口是 HCI（WebSocket + Godot）和 RL（Gymnasium + SB3）。
2. **ShapeIntent 是双模的统一命令接口**。人下达 ShapeIntent（点击/手柄），策略也下达 ShapeIntent（网络输出），同一个 Controller 解算成 `push/rotate` 喂给同一个 NewtonEngine。
3. **RL 学到的策略可零适配加载到 HCI 模式**。因为底层 engine/controller/state 完全相同，不存在 sim-to-sim gap。这是一体化平台的核心价值。
4. **RL env 与 Isaac Lab 接口对齐**。obs/action/reward 契约一致，将来千环境并行是提升不是重写。
5. **路径规划系统（VPP）在双模式中共享**。A* 搜索 → B-spline 平滑 → PlannedPath，HCI 用于可视化，RL 用于 progress/reward。
6. **三种保真度显式化**：guided（运动学演示）/ physics（物理仿真）/ rl（策略推理），API 和 HUD 明确标注，不可混用。
