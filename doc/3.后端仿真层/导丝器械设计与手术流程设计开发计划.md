# 导丝器械设计与手术流程设计开发计划

日期：2026-07-17

## 一、目标与边界

本文用于承接《导丝分段仿真建模与参数设定方案》和《介入导丝大曲率转弯流程引导设计方案》，把“导丝是什么”和“这台手术怎么做”沉淀为后端可配置、可测试、可被前端真实展示的数据模型。

当前项目已经具备以下基础：

- `services/devices/guidewire_profile.py` 已定义 `GuidewireProfile`、`TipShapeProfile`、`GuidewireSegmentParam` 和六段式导丝材料模型。
- `services/devices/support_tube.py` 已定义 `CoaxialSupportSystem`、`SupportTube` 和默认同轴支撑系统。
- `services/physics/newton_engine.py` 已接入导丝分段诊断、支撑状态、扭转滞后、贴壁滑入与顶壁风险指标。
- `services/websocket_handler.py` 已能向前端输出导丝、支撑、屈曲和风险的中文显示字段。
- Godot 前端已开始按 `material_segment` 和 `support_state` 显示导丝分段颜色与支撑 tint。

下一步开发的核心不是再增加孤立字段，而是建立两条稳定主线：

```text
GuidewireDesign：器械本体设计，回答“用哪根导丝”
ProcedureDesign：手术场景设计，回答“从哪里进、到哪里去、按什么流程推进”
```

所有前端显示、训练评分和风险判断都必须能追溯到这两条主线或后端真实运行状态。缺少真实来源时输出 `null`、`unknown` 或明确 fallback，不允许前端凭颜色、屏幕距离或曲率自行伪造风险结论。

## 二、临床参数基线

根据介入导丝综述和血管通路资料，后端第一阶段采用以下建模基线。

### 2.1 导丝长度

| 场景 | 建模长度 |
| --- | ---: |
| 常规导航导丝 | 1450-1800 mm |
| 默认训练导丝 | 1800 mm |
| 交换导丝 | 2600-3000 mm |
| 外周介入长导丝上限 | 3000-3300 mm |

第一阶段默认值：

```python
DEFAULT_GUIDEWIRE_LENGTH_MM = 1800.0
DEFAULT_EXCHANGE_GUIDEWIRE_LENGTH_MM = 3000.0
```

说明：

- 现有 Newton demo 为实时可视化与小场景稳定性，内部 `rod_length_m` 可能远短于真实 1800 mm。
- 新增设计层应区分 `clinical_total_length_mm` 和 `active_sim_length_mm`。
- 前端和总结中展示临床长度，物理求解器可以继续使用缩放后的活跃仿真长度。

### 2.2 导丝直径

| 规格 | 用途 |
| --- | --- |
| 0.014 inch | 冠脉、小血管、神经介入、膝下分支、微导管系统 |
| 0.018 inch | 初始通路、小血管、部分外周病变 |
| 0.035 inch | 外周大血管、导管/鞘管支撑、诊断导管输送 |

第一阶段默认：

```python
diameter_inch = 0.014
radius_mm = 0.1778
```

### 2.3 进针与入路位置

股动脉入路：

```text
access_site = common_femoral_artery
entry_zone = femoral_head_projection
constraints = below_inguinal_ligament + above_cfa_bifurcation
```

桡动脉入路：

```text
access_site = radial_artery
entry_offset_from_radial_styloid_mm = 20.0
acceptable_range_mm = 10.0-30.0
```

第一阶段只把这些信息作为手术场景配置和前端说明，不直接模拟皮肤穿刺、针尖刺入或真实 Seldinger 操作。

## 三、GuidewireDesign 设计

`GuidewireProfile` 已经能描述分段材料和 tip 形状，但还缺少临床器械规格、用途、兼容性和显示摘要。建议新增轻量包装结构 `GuidewireDesign`，并继续复用现有 `GuidewireProfile`。

### 3.1 数据结构

建议新增文件：

```text
services/devices/guidewire_design.py
```

建议结构：

```python
@dataclass(frozen=True)
class GuidewireDesign:
    name: str
    display_name_zh: str
    clinical_total_length_mm: float
    active_sim_length_mm: float
    diameter_inch: float
    radius_mm: float
    exchange_length: bool
    intended_use: tuple[str, ...]
    compatible_support: tuple[str, ...]
    profile: GuidewireProfile

    def summary_zh(self) -> str:
        ...
```

字段说明：

| 字段 | 作用 |
| --- | --- |
| `clinical_total_length_mm` | 真实器械长度，用于文档、前端和训练记录 |
| `active_sim_length_mm` | 当前求解器实际参与仿真的有效长度 |
| `diameter_inch` | 临床规格，决定导管兼容性和默认半径 |
| `radius_mm` | 与现有 `GuidewireSegmentParam.radius_mm` 对齐 |
| `exchange_length` | 是否为交换导丝 |
| `intended_use` | coronary/peripheral/neuro/below_knee 等 |
| `compatible_support` | microcatheter/guiding_catheter/sheath 等 |
| `profile` | 现有六段式材料模型 |

### 3.2 默认 preset

第一阶段实现三个 preset。

#### standard_014_jtip

```text
中文名：0.014 J-tip 标准训练导丝
临床长度：1800 mm
活跃仿真长度：沿用当前 Newton active length
直径：0.014 inch
tip：j_tip
用途：小血管、分支选择、大曲率转弯训练
支撑：microcatheter、guiding_catheter
```

#### exchange_014_jtip

```text
中文名：0.014 J-tip 交换导丝
临床长度：3000 mm
直径：0.014 inch
tip：j_tip
用途：器械交换、保持远端通路
支撑：microcatheter、guiding_catheter
```

#### standard_035_straight_support

```text
中文名：0.035 直头支撑导丝
临床长度：1800 mm
直径：0.035 inch
tip：straight
用途：外周大血管、导管/鞘管输送支撑
支撑：sheath、guiding_catheter
```

### 3.3 与现有 GuidewireProfile 的关系

短期不重写 `GuidewireProfile`。`GuidewireDesign` 是外层临床规格，`GuidewireProfile` 是内层材料/几何分段：

```text
GuidewireDesign
    ├── 临床规格：长度、直径、用途、兼容器械
    └── GuidewireProfile
          ├── TipShapeProfile
          └── GuidewireSegmentParam x 6
```

NewtonEngine 初期继续接收 `GuidewireProfile`，随后扩展为接收 `GuidewireDesign | GuidewireProfile`。如果只传入旧的 `GuidewireProfile`，后端生成默认 `standard_014_jtip` 包装，保持兼容。

## 四、ProcedureDesign 设计

`ProcedureDesign` 描述手术场景、入路、目标路径和器械组合。它不替代 `NavigationEngine`，而是为会话初始化、状态总结和前端 HUD 提供统一上下文。

### 4.1 数据结构

建议新增文件：

```text
services/devices/procedure_design.py
```

建议结构：

```python
@dataclass(frozen=True)
class AccessProfile:
    name: str
    display_name_zh: str
    vessel: str
    vessel_label_zh: str
    entry_zone: str
    entry_zone_label_zh: str
    constraints: tuple[str, ...]
    needle_entry_offset_mm: float | None = None
    needle_entry_range_mm: tuple[float, float] | None = None


@dataclass(frozen=True)
class ProcedureDesign:
    name: str
    display_name_zh: str
    procedure_type: str
    access: AccessProfile
    guidewire_design_name: str
    support_stack: tuple[str, ...]
    target_strategy: str
    requires_large_curvature_guidance: bool = True
```

第一阶段状态集合：

```text

TIP_ORIENTATION
SUPPORT_READY
MICRO_ADVANCE
WALL_SLIDE
STALL_OR_RISK_DETECTED
STRATEGY_SWITCH
PASS_TURN_SUCCESS
```

状态机必须由后端真实指标驱动：

- `torsion_lag_deg`
- `support.free_wire_length_mm`
- `support.support_ratio`
- `buckling.risk_level`
- `normal_poking_score`
- `tangential_slide_score`
- `wall_slide_state`
- 路径进度和目标距离

缺少指标时输出 `unknown`，不自动判定为安全或成功。

## 八、开发红线

- 不得把临床总长度直接强行塞进当前 Newton 小场景求解，必须区分临床长度和活跃仿真长度。
- 不得用前端颜色、屏幕距离或视觉遮挡推断风险、支撑或流程状态。
- 不得在缺少真实力来源时填充假的 `lateral_force_n`、`axial_force_n` 或 `torque_nm`。
- 不得把 `guided` 运动学结果描述为完整物理仿真能力。
- 不得在缺少指标时默认显示“安全”，必须显示 `unknown`、`null` 或中文“未知”。
- 不得让 `GuidewireDesign` 与现有 `GuidewireProfile` 形成两套分段定义；设计层必须复用 profile。

## 九、推荐开发顺序

1. 新增 `GuidewireDesign`、`AccessProfile`、`ProcedureDesign` 及默认 preset。
2. 扩展 `services/devices/__init__.py`，让测试和上层统一导入。
3. 增加配置层单元测试，锁定 0.014/0.035、180 cm/300 cm、股动脉/桡动脉入路参数。
4. 让 `NewtonEngine` 接收设计对象，诊断中输出导丝规格和手术上下文。
5. 让 `state_batch` 输出 `procedure` 和更完整的 `guidewire` 中文摘要。
6. 前端 HUD 显示“术式 / 入路 / 导丝规格 / 进针位置”。
7. 在上述字段稳定后，实现大曲率流程状态机和训练评分事件。

完成第 1-6 步后，系统将从“导丝分段仿真”升级为“具体手术场景下的一根具体导丝”，后续同轴支撑、流程引导和 RL 训练会有统一语义基础。
