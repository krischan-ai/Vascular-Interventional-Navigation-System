# 导丝器械设计与手术流程设计开发计划

日期：2026-07-17

## 一、目标与边界

本文用于承接《导丝分段仿真建模与参数设定方案》和《介入导丝大曲率转弯流程引导设计方案》，把“导丝是什么”和“这台手术怎么做”沉淀为后端可配置、可测试、可被前端真实展示的数据模型。

当前项目已经具备以下基础：

- `services/devices/guidewire_profile.py` 已定义 `GuidewireProfile`、`TipShapeProfile`、`GuidewireSegmentParam` 和六段式导丝材料模型。
- `services/devices/support_tube.py` 已定义 `CoaxialSupportSystem`、`SupportTube` 和默认同轴支撑系统。
- `services/physics/newton_engine.py` 已接入导丝分段诊断、支撑状态、扭转滞后、贴壁滑入与顶壁风险指标。
- `services/websocket_handler.py` 已能向前端输出导丝、支撑、屈曲和风险的中文显示字段。
- Godot 前端已开始按 `material_segment` 和 `support_state` 显示导丝分段颜色与支撑 tint。

下一步开发的核心不是再增加孤立字段，而是建立两条稳定主线：

```text
GuidewireDesign：器械本体设计，回答“用哪根导丝”
ProcedureDesign：手术场景设计，回答“从哪里进、到哪里去、按什么流程推进”
```

所有前端显示、训练评分和风险判断都必须能追溯到这两条主线或后端真实运行状态。缺少真实来源时输出 `null`、`unknown` 或明确 fallback，不允许前端凭颜色、屏幕距离或曲率自行伪造风险结论。

## 二、临床参数基线

根据介入导丝综述和血管通路资料，后端第一阶段采用以下建模基线。

### 2.1 导丝长度

| 场景 | 建模长度 |
| --- | ---: |
| 常规导航导丝 | 1450-1800 mm |
| 默认训练导丝 | 1800 mm |
| 交换导丝 | 2600-3000 mm |
| 外周介入长导丝上限 | 3000-3300 mm |

第一阶段默认值：

```python
DEFAULT_GUIDEWIRE_LENGTH_MM = 1800.0
DEFAULT_EXCHANGE_GUIDEWIRE_LENGTH_MM = 3000.0
```

说明：

- 现有 Newton demo 为实时可视化与小场景稳定性，内部 `rod_length_m` 可能远短于真实 1800 mm。
- 新增设计层应区分 `clinical_total_length_mm` 和 `active_sim_length_mm`。
- 前端和总结中展示临床长度，物理求解器可以继续使用缩放后的活跃仿真长度。

### 2.2 导丝直径

| 规格 | 用途 |
| --- | --- |
| 0.014 inch | 冠脉、小血管、神经介入、膝下分支、微导管系统 |
| 0.018 inch | 初始通路、小血管、部分外周病变 |
| 0.035 inch | 外周大血管、导管/鞘管支撑、诊断导管输送 |

第一阶段默认：

```python
diameter_inch = 0.014
radius_mm = 0.1778
```

### 2.3 进针与入路位置

股动脉入路：

```text
access_site = common_femoral_artery
entry_zone = femoral_head_projection
constraints = below_inguinal_ligament + above_cfa_bifurcation
```

桡动脉入路：

```text
access_site = radial_artery
entry_offset_from_radial_styloid_mm = 20.0
acceptable_range_mm = 10.0-30.0
```

第一阶段只把这些信息作为手术场景配置和前端说明，不直接模拟皮肤穿刺、针尖刺入或真实 Seldinger 操作。

## 三、GuidewireDesign 设计

`GuidewireProfile` 已经能描述分段材料和 tip 形状，但还缺少临床器械规格、用途、兼容性和显示摘要。建议新增轻量包装结构 `GuidewireDesign`，并继续复用现有 `GuidewireProfile`。

### 3.1 数据结构

建议新增文件：

```text
services/devices/guidewire_design.py
```

建议结构：

```python
@dataclass(frozen=True)
class GuidewireDesign:
    name: str
    display_name_zh: str
    clinical_total_length_mm: float
    active_sim_length_mm: float
    diameter_inch: float
    radius_mm: float
    exchange_length: bool
    intended_use: tuple[str, ...]
    compatible_support: tuple[str, ...]
    profile: GuidewireProfile

    def summary_zh(self) -> str:
        ...
```

字段说明：

| 字段 | 作用 |
| --- | --- |
| `clinical_total_length_mm` | 真实器械长度，用于文档、前端和训练记录 |
| `active_sim_length_mm` | 当前求解器实际参与仿真的有效长度 |
| `diameter_inch` | 临床规格，决定导管兼容性和默认半径 |
| `radius_mm` | 与现有 `GuidewireSegmentParam.radius_mm` 对齐 |
| `exchange_length` | 是否为交换导丝 |
| `intended_use` | coronary/peripheral/neuro/below_knee 等 |
| `compatible_support` | microcatheter/guiding_catheter/sheath 等 |
| `profile` | 现有六段式材料模型 |

### 3.3 与现有 GuidewireProfile 的关系

短期不重写 `GuidewireProfile`。`GuidewireDesign` 是外层临床规格，`GuidewireProfile` 是内层材料/几何分段：

```text
GuidewireDesign
    ├── 临床规格：长度、直径、用途、兼容器械
    └── GuidewireProfile
          ├── TipShapeProfile
          └── GuidewireSegmentParam x 6
```

NewtonEngine 初期继续接收 `GuidewireProfile`，随后扩展为接收 `GuidewireDesign | GuidewireProfile`。如果只传入旧的 `GuidewireProfile`，后端生成默认 `standard_014_jtip` 包装，保持兼容。

## 四、ProcedureDesign 设计

`ProcedureDesign` 描述手术场景、入路、目标路径和器械组合。它不替代 `NavigationEngine`，而是为会话初始化、状态总结和前端 HUD 提供统一上下文。

### 4.1 数据结构

建议新增文件：

```text

```

```python

    display_name_zh: str

    entry_zone: str
    entry_zone_label_zh: str
```

### 4.4 冠脉 PCI 完整流程基线

临床冠脉介入通常不是“单根导丝推进”这一件事，而是从术前评估、血管入路、导管到位、造影确认、导丝跨越病变，到球囊/支架沿导丝输送、扩张释放、最终造影和术后抗栓计划组成的连续流程。根据 Merck Manual、StatPearls/NCBI Bookshelf 和 Mayo Clinic 的公开流程描述，第一阶段文档把完整 PCI 流程沉淀为 `ProcedureDesign.clinical_workflow`，但当前物理仿真只覆盖“入路上下文 + 已建立通路后的导丝导航/支撑优化/分支选择”。

推荐流程枚举：

```text
PREOP_PLAN
ACCESS_AND_SHEATH
DIAGNOSTIC_ANGIOGRAPHY
GUIDING_CATHETER_ENGAGEMENT
LESION_ASSESSMENT
CORONARY_GUIDEWIRE_CROSSING
DEVICE_DELIVERY_OVER_WIRE
BALLOON_PREDILATION
STENT_POSITIONING
STENT_DEPLOYMENT
POST_DILATION_OR_OPTIMIZATION
FINAL_ANGIOGRAPHY
WIRE_AND_CATHETER_WITHDRAWAL
POST_PROCEDURE_ANTITHROMBOTIC_PLAN
```

仿真落点：

| 临床步骤 | 第一阶段处理 |
| --- | --- |
| 术前评估、抗血小板/抗凝准备 | 只作为 `procedure` 上下文和训练记录 |
| 桡动脉/股动脉入路、置鞘 | 用 `AccessProfile` 表达，不模拟皮肤穿刺和 Seldinger 细节 |
| 诊断造影、病变评估 | 用目标路径、狭窄/分叉标签表达，不模拟造影剂流体 |
| 指引导管到冠脉开口 | 用 `support_stack` 和支撑状态表达 |
| 导丝跨越病变或大曲率分支 | 当前重点仿真，接入扭转滞后、贴壁滑入、顶壁风险和抗屈曲 |
| 球囊/支架沿导丝输送 | 第一阶段只作为 planned device 和流程事件 |
| 球囊扩张、支架释放、后扩 | 不描述为当前物理能力，后续单独设计设备展开/血管接触模型 |
| 最终造影、撤出器械、术后抗栓 | 作为流程阶段和训练总结，不参与实时物理求解 |

因此，冠脉默认 preset 应优先采用：

```text
clinical_workflow = PREOP_PLAN -> ACCESS_AND_SHEATH -> DIAGNOSTIC_ANGIOGRAPHY -> GUIDING_CATHETER_ENGAGEMENT -> CORONARY_GUIDEWIRE_CROSSING -> DEVICE_DELIVERY_OVER_WIRE -> FINAL_ANGIOGRAPHY
simulated_scope = access_context + guidewire_crossing + support_optimization + branch_selection
planned_devices = guidewire + guiding_catheter + microcatheter + balloon + stent
```

参考来源：

- Merck Manual Professional，Percutaneous Coronary Interventions (PCI)：https://www.merckmanuals.com/professional/cardiovascular-disorders/coronary-artery-disease/percutaneous-coronary-interventions-pci
- StatPearls/NCBI Bookshelf，Percutaneous Coronary Intervention：https://www.ncbi.nlm.nih.gov/books/NBK556123/
- Mayo Clinic，Coronary angioplasty and stents：https://www.mayoclinic.org/tests-procedures/coronary-angioplasty/about/pac-20384761

### 5.5 阶段 E：冠脉 PCI 流程状态机

在导丝和手术上下文稳定后，再实现只读流程状态机。第一阶段覆盖“已建立入路后的冠脉样导丝导航”，不要把完整皮肤穿刺、球囊压力、支架释放描述为已具备物理能力：

```json
"procedure_phase": {
  "phase": "TIP_ORIENTATION",
  "phase_text": "旋转定向",
  "confidence": 0.72,
  "allowed_actions": ["small_push", "small_rotate", "hold"],
  "blocked_actions": ["large_push"],
  "tip_facing_score": 0.72,
  "support_ready": true,
  "micro_advance_state": "READY",
  "advice": "小步推进，观察贴壁滑入",
  "risk_reason": "顶壁风险低，贴壁滑入中等"
}
```

第一阶段状态集合：

```text
UNKNOWN
PREOP_CONTEXT
ACCESS_ESTABLISHED
GUIDING_CATHETER_POSITIONING
TIP_ORIENTATION
SUPPORT_OPTIMIZATION
MICRO_ADVANCE
WALL_SLIDE_NEGOTIATION
BRANCH_SELECTION
STALL_OR_RISK_DETECTED
TARGET_REACHED
WITHDRAW_OR_FINISH
```

状态机必须由后端真实指标驱动：

- `torsion_lag_deg`
- `support.free_wire_length_mm`
- `support.support_ratio`
- `buckling.risk_level`
- `normal_poking_score`
- `tangential_slide_score`
- `wall_slide_state`
- 路径进度和目标距离

缺少指标时输出 `unknown`，不自动判定为安全或成功。

动作建议只输出语义层，不直接接管输入：

```text
small_push
large_push
small_rotate
pull_back
hold
advance_support
exchange_device
```

| `guidewire.torsion_lag_deg` | 扭转滞后 |
| `guidewire.current_tip_segment` | 当前导丝分段 |
| `support.effective_support_type` | 当前支撑器械 |
| `procedure.access_site` | 入路血管 |
| `procedure.needle_entry` | 进针位置 |

```json
  "tangential_slide_score": {"name": "贴壁滑入", "value": "中"},
  "access_site": {"name": "入路血管", "value": "股总动脉"},
```

## 八、开发红线

- 不得把临床总长度直接强行塞进当前 Newton 小场景求解，必须区分临床长度和活跃仿真长度。
- 不得用前端颜色、屏幕距离或视觉遮挡推断风险、支撑或流程状态。
- 不得在缺少真实力来源时填充假的 `lateral_force_n`、`axial_force_n` 或 `torque_nm`。
- 不得把 `guided` 运动学结果描述为完整物理仿真能力。
- 不得在缺少指标时默认显示“安全”，必须显示 `unknown`、`null` 或中文“未知”。
- 不得让 `GuidewireDesign` 与现有 `GuidewireProfile` 形成两套分段定义；设计层必须复用 profile。
- 不得把冠脉 PCI 的完整皮肤穿刺、球囊扩张、支架释放描述为当前已具备的物理能力；第一阶段只能作为流程阶段、事件和调试字段。
- 不得让 `procedure_phase` 在缺少 `torsion_lag_deg`、支撑状态、贴壁/顶壁风险或路径进度时输出“安全”“成功”或“ready”。

## 九、推荐开发顺序

1. 新增 `GuidewireDesign`、`AccessProfile`、`ProcedureDesign` 及默认 preset。
2. 扩展 `services/devices/__init__.py`，让测试和上层统一导入。
3. 增加配置层单元测试，锁定 0.014/0.035、180 cm/300 cm、股动脉/桡动脉入路参数。
4. 让 `ProcedureDesign` 承载冠脉 PCI 临床流程基线、模拟范围和 planned devices。
5. 让 `NewtonEngine` 接收设计对象，诊断中输出导丝规格和手术上下文。
6. 让 `state_batch` 输出 `procedure` 和更完整的 `guidewire` 中文摘要。
7. 前端先用“调试”弹窗展示术式、入路、导丝规格、临床总长、活跃仿真长度和后续 `procedure_phase`，不要提前放入正式 HUD。
8. 在上述字段稳定后，实现冠脉 PCI 已建立入路后的流程状态机。
9. 状态机稳定后，再实现训练评分事件、动作建议和安全保护。

完成第 1-6 步后，系统将从“导丝分段仿真”升级为“具体手术场景下的一根具体导丝”，后续同轴支撑、流程引导和 RL 训练会有统一语义基础。
