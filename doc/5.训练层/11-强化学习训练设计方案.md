## 1. 学完本教程应该理解什么

本教程不把强化学习简化为“一条训练命令”。完成学习后，你应该能够回答：

1. 强化学习与普通有标签训练有什么不同？
2. 导丝、血管和规划路径如何组成训练任务？
3. 训练环境是什么，它与项目虚拟环境（Python）有什么区别？
4. 策略看到了哪些数据，又能输出什么动作？
5. 奖励为什么能让导丝逐渐学会前进？
6. 近端策略优化（Proximal Policy Optimization，PPO）怎样利用采样数据更新策略？
7. 为什么第一次实验选择 4096 步，而不是直接训练 10 万步？
8. 日志、检查点、最佳模型和最终模型分别说明什么？
9. 怎样设计对照实验，才能知道结果为什么变好或变差？
10. 当前项目已有训练结果证明了什么，还缺少什么证据？

整篇教程遵循同一套学习方法：

```text
先解释概念
  → 找到项目中的对应数据和代码
  → 执行一个具体步骤
  → 观察导丝或日志发生了什么
  → 解释这一步的实验意义
```

## 2. 从导丝操作理解强化学习

### 2.1 普通训练与强化学习有什么不同

普通有标签训练通常提供：

```text
输入数据 → 正确答案
```

例如，给模型一张介入影像，并标出导丝尖端位置。模型学习从图像预测尖端坐标。

强化学习（Reinforcement Learning）通常没有人逐步告诉模型“此时必须推进 0.2、旋转 0.1”。模型需要：

```text
观察当前状态
  → 自己选择动作
  → 环境执行动作
  → 获得新的状态和奖励
  → 根据结果调整以后选择动作的方式
```

可以把它想象成一个刚开始练习导丝操作的虚拟操作者：

- 它看到导丝尖端方向、路径方向、进度和接触风险；
- 它决定下一步朝哪里、推进多强；
- 物理引擎计算导丝怎样弯曲和接触血管；
- 沿规划路径前进会得到正向反馈；
- 顶壁、偏离、抖动和失败会得到负向反馈；
- 经过很多次尝试后，它提高有效动作出现的概率。

强化学习不是“随机试到成功后记住整条动作序列”。它要学习的是：

> 在不同导丝状态下，什么动作更可能带来长期的好结果。

### 2.2 八个基础概念

| 概念 | 在本项目中的含义 | 前端可观察现象 |
|---|---|---|
| 智能体（Agent） | 正在学习的导丝控制策略 | 像一个虚拟操作者 |
| 环境（Environment） | 血管、规划路径、控制器和物理引擎 | 导丝运动所在的仿真世界 |
| 观测（Observation） | 策略每一步收到的状态数据 | 尖端朝向、进度、偏差、接触和风险 |
| 动作（Action） | 策略对下一步运动的决定 | 改变目标方向和推进强度 |
| 奖励（Reward） | 环境对刚才动作结果的评分 | 前进加分，顶壁和偏离扣分 |
| 时间步（Timestep） | 一次“观察—动作—环境反馈” | 导丝完成一次控制更新 |
| 回合（Episode） | 从导丝重置到成功、失败或超时 | 一次完整尝试 |
| 策略（Policy） | 根据观测选择动作的方法 | 虚拟操作者当前掌握的操作习惯 |

一次交互可以写成：

```text
观测 s_t
  → 策略选择动作 a_t
  → 环境执行
  → 得到奖励 r_t 和新观测 s_(t+1)
```

这里的字母只是数学简写：

- `s` 表示状态或观测；
- `a` 表示动作；
- `r` 表示奖励；
- `t` 表示当前时间步。

初学阶段不需要先记公式。更重要的是理解：每条训练数据都来自一次真实的环境交互。

## 3. 先分清两种“环境”

项目中经常同时出现两种环境，它们不是同一件事。

### 3.1 项目虚拟环境（Python）

项目虚拟环境 `.venv310` 保存解释器（Python）和训练依赖。

当命令使用：

```bash
.venv310/bin/python
```

就已经明确使用项目虚拟环境。即使终端左侧仍显示 `(base)`，也不代表 `.venv310` 没有生效。

它解决的问题是：

> 用哪个解释器，以及到哪里寻找训练依赖（PyTorch、Gymnasium 和 Stable-Baselines3）？

### 3.2 强化学习训练环境

训练环境（Reinforcement Learning Environment）是策略进行尝试的仿真任务。

本项目的训练环境是：

```text
NavigationGymEnv
  = 血管模型
  + 目标路线
  + 导丝导航引擎
  + 形状意图控制器
  + 牛顿物理引擎（Newton/Warp）
  + 观测、奖励和结束规则
```

它解决的问题是：

> 策略在哪里操作、能看到什么、能做什么、怎样判断结果好坏？

两者的关系是：

```text
项目虚拟环境（Python）
  → 负责运行训练程序

强化学习训练环境
  → 负责产生导丝交互数据
```

## 4. 项目数据怎样变成训练任务

强化学习会在仿真中产生新轨迹，但训练并不是“没有数据”。本项目使用三层数据。

### 4.1 第一层：血管和路线数据

内置主动脉树 `aorta_tree` 的路线文件位于：

```text
src/cathsim/dm/components/phantom_assets/meshes/aorta_tree/routes.json
```

文件中包含：

- 血管入口；
- 18 个目标端点；
- 每个端点对应的路径点；
- 路线长度；
- 路线上各位置的血管半径。

第一次实验选择 `endpoint_0`。它是当前 18 条路线中最短的一条：

```text
路线长度：0.03067 米，约 30.67 毫米
路径点数：9
目标名称：endpoint_0
```

选择短路线的意义不是让最终成绩更好看，而是降低第一次实验中的变量数量：

- 路线短，训练更快；
- 分支选择较少，失败原因更容易观察；
- 可以先验证训练框架，再逐步增加难度。

### 4.2 第二层：物理引擎产生的动态状态

路线文件只说明“应该走哪里”，不能说明导丝此刻发生了什么。

牛顿物理引擎（Newton）每一步产生：

- 导丝尖端位置和方向；
- 导丝弯曲、松弛和屈曲状态；
- 壁面接触和接触力；
- 尖端与规划路径的关系；
- 风险和安全状态。

这些动态状态会被导航环境整理成策略能够读取的观测。

### 4.3 第三层：交互轨迹数据

训练开始后，每一个时间步都会产生一条经验：

```text
当前观测
策略动作
本步奖励
下一观测
是否结束
结束原因
```

一段连续经验组成轨迹（Trajectory）。一个回合结束后，环境重置导丝，再生成下一段轨迹。

因此，本项目的数据流是：

```text
血管与路线静态数据
  + 物理引擎动态状态
  + 策略产生的动作
  ↓
强化学习交互轨迹
  ↓
近端策略优化更新模型
```

## 5. 训练环境是怎样定义的

训练环境通过两个核心操作工作：

```text
reset()：把导丝恢复到回合起点
step(action)：执行一个动作并返回结果
```

### 5.1 重置环境

每个回合开始时，环境会：

- 重置物理引擎；
- 把导丝放回入口；
- 清空上一步动作；
- 清空连续接触时间；
- 记录新的起始进度；
- 返回第一份观测。

这保证每次尝试从可比较的状态开始。

### 5.2 执行一步

策略给出动作后，环境依次执行：

```text
策略输出形状意图
  → 控制器转换成推进和旋转
  → 物理引擎计算导丝运动
  → 导航引擎更新路径进度与风险
  → 环境计算奖励
  → 返回新观测和结束标志
```

一个时间步不是一秒，也不是一个完整回合。它只表示策略完成了一次决策和环境反馈。

## 6. 策略究竟看到了什么

当前训练使用状态字典作为观测。可以把观测分成五组。

### 6.1 尖端姿态

| 观测字段 | 中文解释 | 前端现象 |
|---|---|---|
| `tip_position` | 尖端相对前视目标的位置 | 黄色尖端在下一目标点的哪一侧 |
| `tip_direction` | 尖端当前方向 | 导丝尖端朝向 |
| `previous_action` | 上一步动作 | 刚才希望导丝怎样运动 |

### 6.2 路线引导

| 观测字段 | 中文解释 | 前端现象 |
|---|---|---|
| `target_direction_local` | 局部目标方向 | 下一小段应该朝哪里 |
| `local_tangent` | 当前路线延伸方向 | 蓝色规划路径在此处的方向 |
| `progress` | 路径进度 | 已完成路线的比例 |
| `progress_velocity` | 进度变化 | 正在前进、停滞还是回退 |
| `remaining_distance` | 剩余距离 | 距离目标还有多远 |

### 6.3 路径和几何

| 观测字段 | 中文解释 | 前端现象 |
|---|---|---|
| `deviation` | 路径偏差 | 尖端离蓝色路径多远 |
| `curvature` | 局部曲率 | 当前弯道有多急 |
| `vessel_radius` | 局部血管半径 | 当前血管有多粗 |

### 6.4 接触和安全

| 观测字段 | 中文解释 | 前端现象 |
|---|---|---|
| `contact_force` | 接触力 | 导丝挤压血管壁的程度 |
| `contact_duration` | 连续接触时长 | 是否持续顶壁 |
| `wall_distance` | 壁面距离 | 导丝离血管壁还有多远 |
| `risk_score` | 风险分数 | 当前安全颜色和风险等级 |

### 6.5 为什么不直接输入世界坐标

这些观测会转换到导丝当前位置附近的局部坐标，并按血管半径等尺度归一化。

这样做的意义是让策略学习：

> 相对当前路径，我应该向左、向右、向前还是减速？

而不是死记：

> 世界坐标等于某个固定数值时，必须输出某个动作。

局部表达更有利于把同一种操作规律迁移到路线的其他位置。

## 7. 策略能够输出什么动作

当前教程使用形状意图（ShapeIntent）动作：

```text
[
  目标方向 x,
  目标方向 y,
  目标方向 z,
  推进强度
]
```

前三个数表示尖端希望朝向哪里，最后一个数表示推进强度。

例如：

```text
[0.1, -0.2, 0.97, 0.8]
```

可理解为：

> 主要向前，略微向侧下方调整，并以约 80% 强度推进。

策略不会直接设置导丝每一段的位置。形状意图控制器会把方向和强度转换成推进与旋转，再交给物理引擎：

```text
策略：我想朝这个方向前进
  → 控制器：需要怎样推进和旋转
  → 物理引擎：导丝实际怎样弯曲和移动
```

这种设计保留了导丝接触、扭转滞后、松弛和屈曲等物理现象。

项目还支持直接动作（Direct Action）：

```text
[推进, 旋转]
```

直接动作适合作为对照组，用来判断形状意图是否真的降低了策略学习难度。

## 8. 奖励如何教会导丝前进

### 8.1 奖励不是最终成绩

奖励是每一步的学习信号，不是最终验收结论。

如果只奖励前进，策略可能学会高速顶壁；如果只惩罚接触，策略可能停在入口不动。因此奖励需要同时表达：

- 是否前进；
- 方向是否合理；
- 是否偏离路径；
- 是否持续接触；
- 动作是否平滑；
- 最终是否到达目标。

### 8.2 当前奖励组成

当前代码使用以下主要权重：

```text
进度增加             +2.0 × 归一化进度增量
方向对齐             +0.2 × 对齐程度 × 正向进度
终点附近回退         -1.0 × 回退程度
路径偏离             -0.3 × 归一化偏差
壁面接触             -0.5 × 接触力²
风险                 -0.3 × 风险分数
动作抖动             -0.05 × 相邻动作差²
成功                 +10
普通失败             -10
超时                 -2
```

前端行为与奖励的对应关系如下。

| 前端看到的行为 | 奖励变化 | 希望策略学到什么 |
|---|---|---|
| 尖端沿蓝色路径稳定前进 | 进度和对齐奖励增加 | 保持有效推进 |
| 导丝原地抖动 | 没有进度奖励，并受到平滑性惩罚 | 减少无效动作 |
| 尖端持续顶壁 | 接触和风险惩罚增加 | 停止硬推并调整方向 |
| 尖端偏离路线 | 偏差惩罚增加 | 重新靠近规划路径 |
| 接近终点后回退 | 回退惩罚增加 | 保持已取得的进度 |
| 进度达到 98% | 获得成功奖励并结束回合 | 完成导航任务 |

### 8.3 为什么要记录奖励分量

假设总奖励提高，可能有两种完全不同的原因：

```text
情况一：导丝前进更快、接触更少
情况二：导丝没有成功，只是减少了某一项惩罚
```

所以实验不能只报告总奖励，还必须同时检查：

- 成功率；
- 最大进度和最终进度；
- 结束原因；
- 接触指标；
- 回合步数；
- 前端轨迹是否合理。

## 9. 回合、回报和长期目标

### 9.1 回合怎样结束

当前一个回合在以下情况结束：

- 路径进度达到 98%，记为成功；
- 触发碰撞停止；
- 物理引擎报告结束；
- 达到 300 步，记为超时。

前端上可以理解为：

```text
导丝从入口开始
  → 尝试前进和转向
  → 成功、失败或超时
  → 导丝回到入口
  → 开始下一回合
```

### 9.2 为什么不能只看当前一步

某些动作可能当前没有明显收益，但会为后面创造条件。

例如：

```text
弯道前降低推进并旋转
  → 当前前进较少
  → 后续更容易进入弯道
  → 整个回合更可能成功
```

强化学习会考虑一段轨迹中的累计奖励，也叫回报（Return）。这使策略能够比较短期推进与长期成功。

### 9.3 探索为什么必要

初始策略不知道哪个动作有效，因此需要探索（Exploration）。

探索意味着在相似状态下尝试略有不同的方向和推进强度。没有探索，策略可能永远不会发现更好的动作；探索过强，又会频繁碰壁。

训练算法的作用之一，就是在“继续尝试”和“利用已经学到的经验”之间取得平衡。

## 10. 近端策略优化（PPO）是怎样学习的

### 10.1 策略网络

策略网络（Policy Network）回答：

> 根据当前观测，下一步应该输出什么方向和推进强度？

当前使用多输入策略（MultiInputPolicy）。这里的“多输入”不是同时训练多个模型，而是让策略分别读取尖端姿态、路线引导、接触风险等字典字段，再组合这些信息计算动作。

初始网络接近随机。训练后，它可能逐渐形成：

```text
直路且风险低
  → 对准路径并推进

接近弯道
  → 提前改变目标方向

接触和风险升高
  → 降低强度、旋转或回撤
```

### 10.2 价值网络

价值网络（Value Network）回答：

> 从当前状态继续操作，未来大概能获得多少回报？

例如：

- 路线对齐、持续前进、接触较小的状态，价值通常更高；
- 顶壁、偏离、几乎无法恢复的状态，价值通常更低。

### 10.3 优势

优势（Advantage）可以通俗理解为：

> 这次动作的结果，比模型原来预期的更好还是更差？

- 结果更好：以后在相似状态下提高这个动作出现的概率；
- 结果更差：以后降低这个动作出现的概率。

### 10.4 为什么先采样再更新

近端策略优化不会走一步就立刻修改网络。它先收集一批轨迹：

```text
观测
动作
奖励
下一观测
结束标志
```

当前安装的训练框架默认：

```text
并行环境数量：1
每批采样步数：2048
```

采满 2048 步后，算法计算回报和优势，再多次使用这批数据更新策略网络与价值网络。

### 10.5 为什么要限制更新幅度

如果一次更新过大，策略可能因为一批偶然数据突然改变，原来有效的行为也会消失。

近端策略优化通过裁剪（Clipping）限制新旧策略差异。可以理解为：

> 每次根据新经验调整一小步，观察结果后再继续。

这也是它常被用作第一条强化学习基线的原因：逻辑清楚，训练通常相对稳定。

### 10.6 近端策略优化（PPO）与软演员-评论家算法（SAC）的区别

项目还支持软演员-评论家算法（Soft Actor-Critic，SAC）。

```text
近端策略优化（PPO）
  → 主要使用刚采集的一批经历
  → 更新完成后继续采集新经历

软演员-评论家算法（SAC）
  → 把经历存入经验回放
  → 后续可以多次抽取旧经历学习
```

牛顿物理仿真较慢，经验来之不易，所以经验复用可能有价值。但不能仅凭理论判断哪种算法更好，必须在相同任务和预算下做对照实验。

## 12. 第一次实验应该怎样设计

### 12.1 先提出实验问题

第一次实验的问题不是：

> 4096 步能不能训练出一个安全、通用的导丝策略？

而是：

> 从环境采样、近端策略优化更新、训练期评估、检查点保存到最终模型，这条训练管线能否完整运行？

这类实验叫训练管线实验。

### 12.2 为什么使用 4096 步

当前近端策略优化每批采样 2048 步，因此：

```text
第 1～2048 步
  → 初始策略收集第一批数据
  → 完成第一次策略更新

第 2049～4096 步
  → 更新后的策略收集第二批数据
  → 完成第二次策略更新
  → 保存最终模型
```

选择 4096 的意义是获得两个完整的“采样—更新”循环。

它不是：

- 4096 个回合；
- 4096 秒；
- 4096 次网络更新；
- 策略收敛所需的标准步数。

### 12.3 为什么检查点和评估频率也设为 2048

第一次实验将：

```text
评估频率：2048
检查点频率：2048
```

这样可以在第一批采样附近检查：

- 是否能保存中间模型；
- 是否能创建评估环境；
- 是否能运行 5 个评估回合；
- 是否能生成最佳模型。

如果训练后半段失败，2048 步检查点仍可用于诊断。

### 12.4 实验变量

第一次实验固定：

| 项目 | 固定值 | 原因 |
|---|---|---|
| 血管 | `aorta_tree` | 使用已有主动脉树数据 |
| 路线 | `endpoint_0` | 当前最短路线，便于先验证闭环 |
| 动作 | `shape_intent` | 与导航控制器和前端辅助动作一致 |
| 物理引擎 | `newton` | 验证真实物理训练链路 |
| 算法 | `ppo` | 建立第一条易解释基线 |
| 随机种子 | `0` | 便于复现第一次运行 |
| 训练步数 | `4096` | 两批 2048 步采样 |

只固定一个随机种子是为了管线检查，不足以评价算法稳定性。

### 12.5 验收标准

训练管线通过需要：

- 训练完整结束；
- 状态文件写为已完成；
- 2048 和 4096 步检查点按预期保存；
- 训练期评估正常运行；
- 生成最终模型；
- 观测和奖励没有非有限值；
- 独立评估命令可以加载模型。

它不要求：

- 成功率已经很高；
- 策略已经收敛；
- 策略优于人工或自动导航；
- 能在其他血管上工作；
- 满足医疗安全要求。

```text
  → 牛顿物理引擎计算运动
  → 环境计算进度、接触和奖励
  → 经验写入本批采样
```

达到 2048 步后：

```text
计算每段轨迹的回报
  → 计算动作优势
  → 更新策略网络
  → 更新价值网络
  → 开始第二批采样
```

训练程序不会自动打开三维前端。训练日志中的数值与前端现象对应：

| 日志或评估变化 | 对应的导丝行为 |
|---|---|
| 进度提高 | 尖端沿路线前进 |
| 最大进度高、最终进度低 | 曾前进较远，随后回退 |
| 回合只有几步 | 可能很快触发碰撞或引擎结束 |
| 每回合都是 300 步 | 多数在目标前停滞并超时 |
| 接触积分升高 | 更长时间或更强地接触血管壁 |

## 14. 怎样判断第一次实验结果

### 14.1 管线通过

如果训练完整结束并生成全部关键产物，可以得出：

> 基于项目路线数据、导航环境、牛顿物理引擎和近端策略优化（PPO）的训练闭环可以运行。

这是工程结论，不是策略能力结论。

### 14.2 出现一次更新

如果运行超过 2048 步并进入第二批采样，可以说明：

> 初始策略已经收集一批数据，并至少完成一次基于优势的策略更新。

但一次更新不足以证明策略学会了稳定导航。

### 14.3 奖励提高

奖励提高只说明当前奖励函数下的平均反馈改善。还要检查：

- 成功率是否提高；
- 最大进度和最终进度是否同时提高；
- 接触是否降低；
- 回合是否仍全部超时；
- 前端回放是否出现自然的导丝动作。

### 14.4 评估结果完全相同

不同评估种子得到完全相同结果，通常说明当前环境重置几乎是确定性的，随机种子没有产生可见任务变化。

此时 10 个回合更接近“同一任务重复 10 次”，不能解释为覆盖了 10 种不同情况。

## 15. 用当前已有结果学习实验分析

截至 2026-07-24，项目运行目录提供了以下案例。

### 15.1 未完整结束的 4096 步近端策略优化（PPO）实验

不能把多次启动产生的日志简单相加后宣称实验完成。应使用新实验名称重新完整运行。

### 15.2 默认导丝参数的 20000 步软演员-评论家算法（SAC）实验

最佳模型和最终模型各评估 5 回合：

- 成功率为 0%；
- 全部在 300 步超时；
- 最大进度约 94%～95%；
- 最终没有越过 98% 成功线。

结合前端现象，可以提出三个候选解释：

1. 策略在终点附近无法继续有效推进；
2. 导丝松弛或屈曲使推进没有转化为尖端前进；
3. 奖励和局部目标在最后一段没有提供足够有效的学习信号。

只有进一步对照实验才能区分这些原因。

### 15.3 缩短导丝参数的 20000 步软演员-评论家算法（SAC）实验

该实验使用：

```text
导丝长度：0.012
入口外自由长度：0.006
最大松弛量：0.006
插入边距：0
```

最佳和最终模型在独立 10 回合评估中均成功，约 79～81 步到达目标，记录接触为 0。

可以说明：

> 在固定血管、固定路线和简化导丝参数下，策略能够完成当前简单任务。

不能说明：

- 默认导丝参数也能成功；
- 缩短导丝是成功的唯一原因；
- 复杂分支和未见血管也能成功；
- 不同种子代表不同初始状态；
- 当前接触指标已经完成临床标定。

10 个评估回合的结果完全相同，进一步说明当前任务接近确定性重复。

### 15.4 累计 100000 步软演员-评论家算法（SAC）续训

项目已经从 20000 步模型及其经验回放继续训练 80000 步，累计计数到 100000 步，并保存最终模型。

这证明：

> 模型恢复、经验回放恢复和继续训练流程可以工作。

但尚缺与 20000 步模型相同条件下的独立冻结评估，所以不能只凭训练回报断言 100000 步模型更好。

## 16. 下一轮实验应该怎样设计

可信实验必须明确：

```text
研究问题
假设
唯一主要变化
保持不变的条件
评价指标
通过标准
结论边界
```

### 16.1 实验一：完整复现 4096 步近端策略优化（PPO）

研究问题：

> 近端策略优化训练管线能否完整完成两个采样批次？

主要变化：

- 只更换为新的实验名称；
- 其他参数保持教程命令不变。

通过标准：

- 状态为已完成；
- 4096 步检查点和最终模型存在；
- 独立评估可以执行。

意义：

> 建立后续近端策略优化实验可以信任的最小工程基线。

### 16.2 实验二：评估 100000 步续训是否有效

研究问题：

> 继续训练 80000 步是否优于原来的 20000 步模型？

保持不变：

- 血管和路线；
- 缩短导丝参数；
- 评估种子；
- 评估回合数；
- 成功和安全指标。

比较：

- 20000 步最佳模型；
- 20000 步最终模型；
- 累计 100000 步最佳模型；
- 累计 100000 步最终模型。

意义：

> 判断增加训练预算是否真的改善任务能力，而不是只改善训练曲线。

### 16.3 实验三：默认导丝与缩短导丝对照

研究问题：

> 导丝长度、自由长度和松弛量是否是终点前停滞的主要原因？

只改变：

- 导丝物理参数。

保持不变：

- 算法；
- 路线；
- 奖励；
- 训练步数；
- 随机种子；
- 评估方式。

观察前端：

- 推进是否转化为尖端前进；
- 是否出现更多松弛和屈曲；
- 是否持续顶壁；
- 是否在 94%～95% 附近停滞；
- 是否需要更多旋转和回撤。

意义：

> 把“策略没有学会”和“物理条件使任务更难”区分开。

### 16.4 实验四：形状意图与直接动作对照

研究问题：

> 形状意图是否比直接输出推进和旋转更容易学习？

只改变：

```text
shape_intent ↔ direct
```

比较：

- 成功率；
- 达到同一进度需要的训练步数；
- 动作平滑性；
- 接触；
- 超时率。

意义：

> 验证控制抽象是否真的提高学习效率，而不是凭直觉保留一种动作形式。

### 16.5 实验五：近端策略优化（PPO）与软演员-评论家算法（SAC）对照

研究问题：

> 在同样的物理采样预算下，经验复用是否带来更好的学习效果？

保持不变：

- 环境；
- 动作；
- 奖励；
- 路线；
- 训练时间步；
- 评估种子。

注意：

近端策略优化和软演员-评论家内部更新次数不同，所以应同时报告：

- 环境交互步数；
- 实际训练时间；
- 最终成功率；
- 安全指标。

### 16.6 实验六：多随机种子

单个训练种子可能偶然得到较好或较差结果。正式实验至少使用多个训练种子，例如：

```text
0、1、2、3、4
```

报告：

- 平均值；
- 标准差；
- 每个种子的原始结果；
- 所有失败，而不是只展示最佳模型。

当前环境几乎是确定性的，后续还需要真正改变初始姿态、物理参数或路线，随机种子才会产生有意义的任务差异。

### 16.7 实验七：逐步增加路线难度

当 `endpoint_0` 结果稳定后，再按路线长度、曲率和分支难度增加任务：

```text
短路线
  → 单弯路线
  → 长路线
  → 多分支路线
  → 错误姿态恢复
```

这种从易到难的安排称为课程学习（Curriculum Learning）。

每次晋级只改变路线难度，不要同时修改算法、奖励和导丝参数，否则无法判断性能变化来自哪里。

## 17. 训练、验证和测试数据怎样划分

当项目从一条路线扩展到多血管数据时，需要在训练前划分数据。

### 17.1 训练数据

用于策略学习，可以包含：

- 多条血管路线；
- 自动导航轨迹；
- 人工操作轨迹；
- 策略自己产生的轨迹；
- 失败后的人工纠正轨迹。

### 17.2 验证数据

用于：

- 选择最佳模型；
- 调整奖励和训练参数；
- 决定是否进入下一课程阶段。

验证结果参与开发决策，所以不能当作最终测试成绩。

### 17.3 测试数据

只在方案确定后用于最终评价：

- 未参与训练的血管；
- 未参与参数选择的路线；
- 冻结的物理条件和评估规则。

同一患者或同一原始血管产生的不同路线、缩放和变形版本必须放在同一个分组，避免模型在测试集中再次看到相同几何。

人机交互数据的采集、审核和数据集制作流程见第 13 篇教程。

## 18. 安全指标为什么不能只放进奖励

奖励用于学习，安全门槛用于限制风险。两者作用不同。

策略输出动作后，安全保护层（Safety Shield）应能够：

- 限制动作范围；
- 在接触风险上升时减速；
- 必要时回撤或冻结；
- 触发严重风险时终止回合；
- 允许人工随时接管。

训练和评估应单独报告：

- 最大接触；
- 接触积分；
- 最小壁面距离；
- 穿透事件；
- 屈曲事件；
- 错误分支；
- 安全保护层干预次数。

如果策略成功率很高，但每一步都依赖安全层纠正，仍不能说明策略本身合格。

当前接触信息已经进入训练环境，但屈曲、错误分支、穿透和安全干预等完整统计尚未全部接入。文档中的完整安全体系是后续目标，不能当作当前已经实现。

## 19. 常见误解

### 19.1 训练命令运行了，就是模型学会了

错误。命令运行只证明程序开始采样。还要检查训练是否完整结束、模型是否生成以及独立评估结果。

### 19.2 奖励变高，就是成功率变高

错误。策略可能只是减少某项惩罚，却仍然全部超时。

### 19.3 4096 步是一个完整训练规模

错误。它是两个近端策略优化（PPO）采样批次，主要用于验证训练管线。

### 19.4 10/10 成功就代表泛化

错误。如果环境没有随种子变化，10 个回合可能只是同一确定性任务重复 10 次。

### 19.5 修改配置文件（YAML）就改变了训练

当前不成立。现有训练入口不会自动读取这些配置文件，应检查 `run_config.json`。

### 19.6 没有三维画面就是训练失败

错误。当前训练采用无界面方式。是否运行应看采样进度、日志、检查点和进程状态。

### 19.7 终端显示基础环境（base）就没有使用项目虚拟环境

错误。命令显式调用 `.venv310/bin/python` 时，使用的就是项目解释器。

## 20. 本教程的完整学习闭环

从零搭建本项目强化学习训练框架，可以总结为：

```text
理解强化学习的观察—动作—反馈循环
  → 用 aorta_tree 和 endpoint_0 定义任务数据
  → 用 NavigationGymEnv 定义观测、动作、奖励和结束条件
  → 用形状意图连接策略与真实导丝控制
  → 理解近端策略优化（PPO）的采样、优势和限制更新
  → 用 4096 步验证两个采样—更新循环
  → 检查配置、日志、检查点和最终模型
  → 用独立评估检查成功、进度、接触和结束原因
  → 根据结果提出单变量对照实验
  → 从简单路线扩展到多种子、多路线和未见血管
```

判断任何一次训练时，始终回答四个问题：

1. 这次实验想验证什么？
2. 除了研究变量，还有什么发生了变化？
3. 导丝在前端实际表现出什么行为？
4. 现有证据支持什么结论，又不支持什么结论？

强化学习实验的价值不在于训练步数越大越好，而在于每一次实验都能把“数据、环境、算法、行为和结论”连成一条可解释、可复现的证据链。
