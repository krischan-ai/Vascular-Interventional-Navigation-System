# 强化学习训练设计方案：基于 ShapeIntent 的介入导丝自主导航

> 版本：v1.0  
> 日期：2026-07-20  
> 适用平台：Newton/Warp 物理引擎 + NavigationEngine + ShapeIntentController + Gymnasium + Stable-Baselines3  
> 目标：训练可在多血管几何、多物理参数和安全约束下完成导丝自主导航，并可加载到 Godot 人机交互平台中进行策略推理与回放验证。

---

## 1. 方案摘要

现有技术文档已经确定了正确的控制边界：

```text
RL Policy / Human
      │
      ▼
ShapeIntent（目标方向 / waypoint / 推进强度）
      │
      ▼
ShapeIntentController
      │
      ▼
push / rotate
      │
      ▼
NavigationEngine → Newton PhysicsEngine
```

强化学习策略不得直接修改导丝分段位置，也不得通过“软拉向中心线”的方式注入运动学约束。策略只输出高层控制意图，由控制器转化为真实推进和旋转，再由纯物理引擎产生接触、扭转滞后、屈曲和壁面作用力。

本方案建议采用“三类数据 + 六阶段训练”的总体路线：

1. **公开血管数据**：用于生成多样化 STL、中心线、半径场、血管图和 SDF。
2. **公开介入影像数据**：用于预训练导丝分割、尖端定位、碰撞识别和动作识别模型。
3. **平台自采轨迹数据**：由 autopilot、人工操作和已有策略产生，是行为克隆、恢复学习和离线分析的核心数据。
4. **先状态策略，后视觉策略**：先用仿真真值状态训练导航能力，再训练视觉感知并进行策略蒸馏。
5. **先模仿学习，后在线强化学习**：避免从随机动作开始探索造成大量无效碰壁。
6. **安全监督器独立于策略**：训练和部署阶段均由 Safety Shield 限速、回撤、冻结或终止危险动作。

## 2. 对现有架构的继承与修订

### 2.1 继承内容

现有文档已经具备以下训练基础：

- `ShapeIntentController` 将方向或 waypoint 意图解算为真实 `push/rotate`。
- `NavigationEngine` 已提供 progress、deviation、curvature、risk、contact、wall distance 等状态。
- `NewtonEngine` 提供力驱动、J-tip、扭转传递、接触与屈曲等高保真物理。
- Gymnasium 环境可直接在进程内运行，训练时绕过 Godot 和 WebSocket。
- 路由可天然构成 curriculum：直短路径、单弯、锐弯、多分支和全树导航。
- 人机模式与 RL 模式共用控制层和物理层，可减少训练与部署之间的代码路径差异。

### 2.2 建议修订

#### 动作表示

文档定义的推荐动作是：

```text
action = [desired_direction_x, desired_direction_y, desired_direction_z, intensity]
```

该表示可保留，但应增加以下约束：

1. 对前三维进行归一化；模长小于阈值时保持上一方向或使用局部切向。
2. 方向应优先使用导丝尖端局部坐标系表达，避免策略学习全局坐标旋转。
3. 后续可增加更容易训练的三维版本：

```text
action_local = [yaw_offset, pitch_offset, intensity]
```

由环境根据 `tip_direction` 和局部法向基构造 `target_direction`，再封装为 ShapeIntent。

#### 部分可观测性

导丝导航不是严格的完全可观测马尔可夫过程。仅依赖尖端位置和方向，无法完整表示：

- 扭矩是否已传到远端；
- 导丝中段是否蓄积松弛；
- 是否即将发生屈曲；
- 当前接触是瞬时接触还是持续顶壁；
- 相同尖端位姿下不同杆身形状所对应的后续响应。

因此至少加入三帧历史堆叠；更高阶段使用 GRU/LSTM 或 Recurrent PPO，并增加导丝形状摘要、上一动作、推进速度、旋转速度和接触持续时间。

## 3. 公开数据集调研与使用建议

公开资源不能直接提供与本平台完全对齐的 `(obs, ShapeIntent, push, rotate, next_obs, force)` 转移数据。其价值主要分为三类：血管几何、仿真基线和影像感知。

### 3.1 血管几何数据

| 数据集 | 主要内容 | 本项目用途 | 优先级 | 注意事项 |
|---|---|---|---|---|
| Vascular Model Repository（VMR） | 正常与病变心血管计算模型，可下载模型工程压缩包，覆盖主动脉、脑血管、冠脉等 | 快速获得可用表面模型；建立首批跨几何训练集；验证 STL→中心线→SDF 流程 | P0 | 逐模型核查许可、坐标、闭合性、入口出口和网格质量 |
| AVT / SEG.A | 56 例多中心主动脉血管树 CTA 及人工分割，Figshare 约 5.88 GB | 主动脉弓及头颈分支导航；适合当前 endpoint curriculum | P0 | 同一患者的 CTA、mask、STL 和派生路线必须属于同一 split |
| AortaSeg24 | 100 个 CTA 体数据，标注 23 个主动脉分支和区域 | 构建带分支语义的路线库；训练多目标条件策略 | P1 | 通常需在 Grand Challenge 注册并接受数据条款 |
| ImageCAS | 约 1000 个冠状动脉 CTA 及分割 | 扩展至细小、高曲率、密集分支结构；评估几何泛化 | P1/P2 | 冠脉尺度与主动脉差异大，需重新标定导丝直径、刚度、SDF 分辨率和时间步长 |
| MSD Task08 Hepatic Vessel | 443 例肝血管 CT，其中 303 训练、140 测试；CC BY-SA 4.0 | 作为异域树状血管拓扑泛化集；验证算法不是只记忆主动脉弓 | P2 | 不是目标临床通路，不宜作为第一阶段主训练集 |

### 3.2 开源仿真与训练基线

| 资源 | 主要内容 | 本项目用途 | 注意事项 |
|---|---|---|---|
| CathSim | 开源血管内介入仿真环境，提供 Gym 接口、SAC 训练示例、轨迹结果、力反馈和自定义血管网格流程 | 用作 MuJoCo 基线；对比奖励、动作定义、训练速度和成功率；复用数据记录格式思路 | 项目许可限定非商业用途；其物理、资产和本项目 Newton 引擎不同，不能直接把策略权重当作可迁移模型 |
| VMR + SimVascular/VMTK 工具链 | 血管模型、中心线和几何处理生态 | 自动生成 surface、centerline、radius、graph 和入口出口 | 需对网格平滑、封口、分支保真和单位进行自动质检 |

### 3.3 介入影像和感知数据

| 数据集 | 公开内容 | 可训练任务 | 与 RL 的关系 |
|---|---|---|---|
| CathAction | 约 50 万标注帧，约 2.5 万导管/导丝分割掩码；包含动作理解、碰撞检测和五类动作标签 | 动作识别、碰撞识别、导丝/导管分割、视觉编码器预训练 | 适合感知和辅助监督；动作标签较粗，不能直接还原连续 push/rotate |
| Guide3D | 8746 个双平面、人工标注的高分辨率透视样本，包含两类导丝及有/无液体条件 | 导丝分割、双平面三维重建、视觉状态估计 | 适合训练从 X-ray 到 tip/shape 的观测模型，再将其接入已训练的状态策略 |
| Vascular-Guidewire-Datasets | 41 个 DSA 序列、超过 4000 帧、导丝尖端标注 | 尖端检测、时序跟踪、辅助分割 | 规模较小，适合作为外部验证集；许可信息应在使用前单独核查 |
| Soft Robot Guidewire Navigation 研究 | 36 种模块化分叉几何、647 条演示，强调 recovery demonstrations | 借鉴模仿学习、恢复数据和未见几何测试设计 | 项目页面未明确提供完整原始演示下载，不作为本方案的数据依赖 |

### 3.4 推荐下载顺序

第一批只下载并加工：

1. VMR：选择 5～10 个主动脉/头颈模型。
2. AVT：选择 20～30 个质量较高病例建立主动脉主训练集。
3. CathSim：用于环境和算法基线对照。
4. CathAction：先下载动作/碰撞子集，不必一开始处理全部影像。
5. Guide3D：在状态策略收敛后再启动视觉阶段。

ImageCAS 和 MSD 放在跨尺度、跨器官泛化阶段，不应阻塞第一版 RL 环境。

## 4. 血管几何数据加工管线

### 4.1 标准化流程

```text
CTA / segmentation / surface model
        │
        ├─ 单位和坐标统一（m，右手坐标）
        ├─ 连通域清理、孔洞修补、入口出口封口
        ├─ Marching Cubes / surface extraction
        ├─ 保拓扑平滑与适度降面
        ├─ 中心线与半径提取
        ├─ 分支图构建和入口/目标识别
        ├─ route 枚举与难度评分
        ├─ SDF 构建
        └─ 自动质量检查
```

每个 case 输出：

```text
data/vascular_cases/<case_id>/
  manifest.json
  source/
    image.nii.gz
    segmentation.nii.gz
  geometry/
    visual.stl
    collision.stl
    sdf.nrrd
  navigation/
    centerline.json
    graph.json
    routes.json
    radius_profile.json
  qc/
    report.json
    preview.png
```

### 4.2 几何质量门槛

进入训练集前必须通过：

- mesh 为闭合、可定向的二维流形；
- 无大面积自交和重复三角面；
- SDF 内外符号正确；
- 中心线位于血管腔内；
- 半径大于导丝外径与安全余量；
- 入口到目标存在连通路径；
- 路线曲率、分支角、最小半径和路径长度可计算；
- Newton reset 后导丝不会初始穿壁或爆炸；
- autopilot 至少可在低随机化设置下完成基本可达性测试。

### 4.3 防止数据泄漏

数据拆分必须以患者或原始几何为单位，而不是按 route 拆分。同一患者生成的：

- 原始 STL；
- 不同平滑版本；
- 不同中心线路线；
- 镜像、缩放和随机形变版本；

必须全部放在同一个 train/validation/test 集中。

建议拆分：

```text
训练集 70%
验证集 15%
测试集 15%
```

另外保留一个完全不参与调参的 `challenge_holdout`，由不同数据来源组成，例如使用 VMR/AVT 训练，AortaSeg24 或独立 VMR 模型作为最终测试。

## 5. 平台自采轨迹数据设计

### 5.1 为什么必须自采

公开影像数据缺少与本平台同步的：

- ShapeIntent；
- 实际 push/rotate；
- 尖端与杆身三维状态；
- 接触力、壁距、穿透量和风险；
- Newton 物理参数；
- 目标 route 与 progress；
- 失败原因和恢复动作。

因此必须将 HCI、autopilot 和 RL 统一接入轨迹记录器。

### 5.2 轨迹来源

1. **Scripted Autopilot**：快速生成成功轨迹和基础恢复轨迹。
2. **人工操作**：由熟悉导丝操作的人员完成路线，记录更自然的推拉旋转组合。
3. **扰动恢复**：主动把导丝置于错分支、顶壁、过度旋转、松弛和轻度屈曲状态，再采集恢复动作。
4. **旧策略回放**：收集策略失败附近的状态，通过人工或 autopilot 纠正，形成 DAgger 数据。
5. **随机策略**：只用于覆盖安全边界和训练碰撞分类器，不直接用于行为克隆。

### 5.3 单步数据格式

```text
episode_id
case_id / route_id / split
timestamp / step
obs_t
  tip_position
  tip_direction
  progress
  deviation
  tangent
  curvature
  wall_distance
  contact_force
  risk_score
  wire_shape_summary
  action_history
shape_intent_t
low_level_action_t
  push
  rotate
obs_t+1
reward_components
termination_reason
engine_params
controller_params
policy_source
  human / autopilot / rl / recovery
```

建议使用 Zarr 或 HDF5 保存高频数组，Parquet 保存 episode 索引和统计信息。每次实验必须保存代码 commit、数据版本、环境配置和随机种子。

## 6. 强化学习任务定义

### 6.1 Observation

第一版状态策略：

```text
tip_position_local        3
tip_direction_local       3
target_direction_local    3
progress                  1
deviation_normalized      1
local_tangent             3
curvature_normalized      1
wall_distance_normalized  1
contact_force_normalized  1
risk_score                1
previous_action           3 or 4
progress_velocity         1
contact_duration          1
```

应优先使用相对量和局部坐标：

- 位置相对下一前视点；
- 方向相对局部中心线切向；
- 距离按局部血管半径归一化；
- 接触力按校准阈值归一化；
- 曲率按当前训练集分位数归一化。

第二版加入：

- 导丝杆身 8～16 个采样点的局部位置；
- 松弛量、扭转滞后估计、最大弯曲能；
- 最近 3～8 帧状态堆叠；
- 视觉编码器输出。

### 6.2 Action

主策略：

```text
[yaw_offset, pitch_offset, intensity]
```

环境重建 `target_direction` 后生成 ShapeIntent。

对照实验：

```text
A. ShapeIntent 4D: direction_xyz + intensity
B. ShapeIntent 3D: yaw + pitch + intensity
C. Direct 2D: push + rotate
```

预期主策略使用高层 ShapeIntent；Direct 模式仅作为控制难度和样本效率基线。

### 6.3 Reward

奖励主项必须是中心线弧长增量，而不是绝对坐标距离。

建议第一版：

```text
r_progress = clip(Δs / Δs_ref, -1, 1)
r_align    = dot(tip_direction, local_tangent)
p_dev      = clip(deviation / local_radius, 0, 2)
p_contact  = clip(contact_force / force_ref, 0, 2)^2
p_risk     = risk_score
p_smooth   = ||action_t - action_t-1||²

reward =
    2.0 * r_progress
  + 0.2 * r_align
  - 0.3 * p_dev
  - 0.5 * p_contact
  - 0.3 * p_risk
  - 0.05 * p_smooth
```

终局奖励初始值：

```text
到达目标             +10
进入错误终末分支      -5
穿壁/严重碰撞         -10
持续屈曲或安全冻结     -8
超时                  -2
```

这些权重仅作为仿真调试初值，不代表临床安全阈值。`force_ref`、穿透阈值和风险阈值应通过物理标定、phantom 实验或专家评审确定。

### 6.4 Episode 终止条件

`terminated=True`：

- 到达目标区域并持续若干步；
- 穿透量超过硬阈值；
- 接触力超过硬阈值并持续；
- 明确进入错误终末分支；
- 严重屈曲或导丝数值失稳；
- Safety Shield 触发不可恢复停止。

`truncated=True`：

- 超过最大控制步数；
- 长时间无进度；
- 长时间在局部区域循环；
- 仿真计算异常。

### 6.5 控制频率

Newton 物理可保持 60 Hz，策略不必每个物理步都决策。建议：

```text
physics_hz = 60
action_repeat = 3～6
policy_hz = 10～20
```

控制器在两个策略动作之间保持或平滑插值 ShapeIntent，有利于降低策略抖动和训练难度。

## 7. 安全强化学习设计

### 7.1 Safety Shield

Safety Shield 位于策略与 Controller/PhysicsEngine 之间：

```text
policy action
    │
    ▼
action validation
    │
    ├─ 方向与强度限幅
    ├─ 接触力门控推进
    ├─ 壁距过小时禁止继续推进
    ├─ 屈曲风险时回撤
    ├─ 连续无进度时旋转扫掠
    └─ 硬阈值触发 SAFE_HOLD
```

策略不能关闭 Safety Shield。训练时需要在 `info` 中记录 shield 是否修改了动作，以避免表面成功但完全依赖安全层。

### 7.2 约束指标

除 reward 外，单独记录 cost：

```text
cost_contact
cost_penetration
cost_buckling
cost_wrong_branch
cost_shield_intervention
```

后续可引入约束强化学习，但第一版先使用硬安全层 + 奖励惩罚，降低工程复杂度。

## 8. 六阶段训练路线

### 阶段 S0：环境正确性与基线

目标：

- `reset/step` 稳定运行；
- obs 无 NaN/Inf；
- reward 各分量可解释；
- 随机策略明显差于 autopilot；
- autopilot 可在简单路线稳定到达。

输出：

- direct-action baseline；
- scripted autopilot baseline；
- 每条 route 的可达性和难度报告。

### 阶段 S1：行为克隆预训练

数据：

- autopilot 成功轨迹；
- 人工成功轨迹；
- 少量回撤和旋转恢复轨迹。

训练：

- MLP/GRU policy；
- 预测 ShapeIntent；
- 对方向使用余弦损失，对 intensity 使用回归损失；
- 对 recovery 数据提高采样权重。

验收：

- 简单路线无在线 RL 时成功率达到可用水平；
- 动作平滑；
- 不出现长期零推进或持续满强度顶壁。

### 阶段 S2：简单路线在线 RL

算法建议：

- 主线先用 PPO，便于稳定迭代和观察 reward 行为；
- 同时用 SAC 做样本效率对照；
- 使用 BC 权重初始化策略；
- 先关闭大范围 domain randomization。

路线：

```text
Stage 0：直短路线
Stage 1：单弯路线
```

验收：

- 训练几何成功率 ≥95%；
- 验证几何成功率 ≥90%；
- 相比 autopilot 不增加严重接触事件；
- 5 个随机种子结果稳定。

### 阶段 S3：复杂 curriculum 与恢复学习

逐步加入：

- 锐弯、多分叉、错误分支；
- 起点扰动；
- 错误姿态初始化；
- 轻度顶壁和松弛状态；
- 目标条件化和多 route 训练；
- 专门的 recovery episode。

使用自动课程：

- 最近窗口成功率高于阈值则增加难度；
- 成功率下降时混入上一阶段简单样本；
- 不按固定训练步数盲目晋级。

### 阶段 S4：Domain Randomization 与跨几何训练

随机化内容：

- 摩擦；
- 导丝弯曲/扭转/轴向刚度；
- J-tip 角度；
- 推进与旋转增益；
- 时间延迟与控制噪声；
- 血管半径缩放；
- SDF 边界噪声；
- 起点、目标和初始松弛；
- 中心线和视觉配准误差。

随机化范围采用逐步扩大方式，先从标称值 ±5% 开始，再扩展到通过 phantom 标定得到的合理区间。

### 阶段 S5：视觉策略与感知误差训练

训练顺序：

1. CathAction/Guide3D/DSA 数据训练分割、tip tracking、碰撞检测。
2. 在仿真中生成对应 X-ray/roadmap 或二维投影。
3. 用感知网络输出估计 tip、shape、wall/contact 风险。
4. 将已训练状态策略作为 teacher，训练视觉 student。
5. 加入遮挡、噪声、运动模糊、对比剂消散和配准漂移。
6. 视觉策略在 Newton 环境中小步在线微调。

不建议第一版从原始像素端到端 PPO 开始训练，成本高、收敛慢且难以定位失败原因。

## 9. 算法选择

### 9.1 PPO

优点：

- 训练行为较稳定；
- 易于结合 curriculum；
- 对 reward 调试直观；
- 适合先建立可信基线。

缺点：

- on-policy，样本效率较低；
- Newton 环境速度不足时训练成本较高。

用途：第一条主线、课程学习、Recurrent PPO。

### 9.2 SAC

优点：

- 连续动作；
- off-policy，样本复用率高；
- 适合昂贵仿真环境。

缺点：

- 对奖励尺度和 replay 数据分布敏感；
- 可能利用仿真漏洞；
- curriculum 切换时 replay buffer 需要分阶段或加 stage 标签。

用途：与 PPO 并行对照；在环境稳定后作为效率主线候选。

### 9.3 模仿学习

建议使用：

- Behavior Cloning：策略初始化；
- DAgger：收集当前策略错误附近的专家纠正；
- Recovery-focused sampling：提高错分支、顶壁和屈曲恢复样本比例。

暂不把逆强化学习作为第一版主线。已有研究表明，奖励塑形在部分导丝导航任务上可能优于从专家演示反推奖励；本平台已有 progress、contact、risk 等结构化信号，直接奖励塑形更易验证。

## 10. 训练评估体系

### 10.1 核心指标

成功类：

- Target Success Rate；
- Wrong-Branch Rate；
- Timeout Rate；
- Recovery Success Rate。

效率类：

- 到达时间；
- 路径效率：实际尖端轨迹长度 / 中心线路径长度；
- 推进距离、回撤距离和旋转总量；
- 无进度步数比例。

安全类：

- 最大接触力；
- 接触力时间积分；
- 最小壁距；
- 穿透事件数；
- 屈曲事件数；
- Safety Shield 干预率。

泛化类：

- 未见患者几何成功率；
- 未见分支角和半径范围成功率；
- 未见物理参数成功率；
- 感知噪声和延迟下成功率。

### 10.2 测试矩阵

```text
A. 训练几何 + 标称物理
B. 验证几何 + 标称物理
C. 未见几何 + 标称物理
D. 未见几何 + 参数随机化
E. 未见几何 + 感知噪声
F. 恢复状态集合
G. 人工操作 / autopilot / RL 三方对照
```

每个模型至少使用 5 个随机种子，并报告均值、标准差和置信区间。不得只报告最佳模型或单次运行。

### 10.3 最终准入标准

策略进入 HCI 的 `RL_ASSIST` 模式前，应满足：

- 未见几何成功率达到项目设定阈值；
- 严重穿透事件为零或低于硬门槛；
- Safety Shield 干预率不高于基准；
- 失败时能进入 SAFE_HOLD，不持续输出危险动作；
- replay 可完整复现动作、状态和安全事件；
- 性能不依赖 guided/Kinematic 模式；
- 所有测试均在 Newton 物理模式完成。

## 13. 第一版最小可行训练方案

第一版不需要等待所有公开数据处理完成，建议立即实施：

1. 使用现有 `aorta_tree` 和 3～5 个 VMR/AVT 几何。
2. 建立 `NavigationGymEnv` 和轨迹记录器。
3. 使用 autopilot 采集 2 万～10 万个状态转移。
4. 对 ShapeIntent 策略进行行为克隆。
5. 使用 PPO 在直短和单弯路线微调，SAC 作为对照。
6. 每个 episode 随机起点、J-tip 初始角和轻微摩擦。
7. 固定保留至少 2 个从未参与训练的患者几何。
8. 达到验证标准后再增加 CathAction/Guide3D 视觉支线。
9. 训练完成后在 Godot 中以 `RL_ASSIST` 加载，并保留 ESC 人工接管和 Safety Shield。

该路线能最快验证最重要的问题：ShapeIntent 是否是合适的策略动作层、Newton 环境能否支持稳定训练、策略是否能在未见血管几何上超过现有 autopilot。

## 14. 主要风险与控制措施

| 风险 | 表现 | 控制措施 |
|---|---|---|
| 仿真速度不足 | PPO 训练时间过长 | action repeat、无渲染、多进程、缓存几何、后续批量 Warp/Isaac Lab |
| 奖励投机 | 策略原地旋转、贴壁刷进度 | 分量日志、路径单调投影、接触积分、动作成本、失败回放 |
| 几何泄漏 | 测试 route 与训练来自同一患者 | 按 patient/case 拆分所有派生资产 |
| 过度依赖中心线 | 策略仅会追踪理想路径 | 中心线扰动、局部 waypoint、错误路线恢复、视觉与接触输入 |
| 只会成功不会恢复 | 错分支后长时间卡住 | recovery demonstrations、失败状态 reset、DAgger |
| 安全层替策略兜底 | 高 shield 干预但表面成功 | 单独报告干预率，训练时惩罚反复干预 |
| 视觉 sim-to-real 差异 | 仿真图像策略在真实 X-ray 失效 | 公开影像预训练、域随机化、状态 teacher→视觉 student |
| 数据许可不一致 | 无法商用或发布模型 | 建立逐数据集许可清单；CathSim 等非商业资源与自有资产隔离 |

## 15. 结论

强化学习训练的第一优先级不是堆叠更复杂的网络，而是完成以下闭环：

```text
多样血管几何
   → 标准化 STL/centerline/SDF/routes
   → Newton Gym 环境
   → 统一轨迹记录
   → autopilot/人工示范
   → BC 初始化
   → PPO/SAC curriculum
   → 安全与恢复评估
   → Godot RL_ASSIST 推理
```

公开数据应作为“几何和感知数据源”，而不是被误认为可直接训练控制策略的完整 transition dataset。平台真正有价值的数据资产，是与同一 Newton 物理、同一 ShapeIntentController 和同一 NavigationState 对齐的内部轨迹库。该轨迹库一旦建立，后续行为克隆、在线 RL、离线分析、视觉蒸馏、回放评分和 sim-to-real 标定都可以在同一数据标准上持续迭代。
