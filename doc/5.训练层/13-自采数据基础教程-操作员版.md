# 自采数据基础教程：导丝操作员版

> 版本：1.1  
> 日期：2026-07-21  
> 适用对象：不参与软件开发、负责在 CathSim（导丝仿真平台）上操控导丝并配合完成训练数据采集的工作人员  
> 配套方案：[11-强化学习训练设计方案.md](11-强化学习训练设计方案.md)、[12-自采数据训练方案与数据收集清单.md](12-自采数据训练方案与数据收集清单.md)  
> 使用范围：仅用于仿真平台的数据采集和质量检查，不得作为真实患者介入操作指南

## 1. 这份教程解决什么问题

本教程帮助操作员完成两件事：

1. 按统一流程操控仿真导丝，获得可以用于训练或评估的数据；
2. 在现场判断一条记录是“可以进入正式数据集”“需要复核”还是“技术性作废”。

操作员不需要理解程序代码，也不需要手工编辑数据文件。操作员的核心职责是：

- 确认任务、模型、路线和控制模式正确；
- 按要求完成成功导航、失败恢复或人工纠正；
- 遇到风险时采取正确动作，不为追求成功率强行推进；
- 如实记录结果，失败数据不能隐瞒或删除；
- 发现连接、画面、导丝运动或记录异常时立即停止采集并上报。

### 阅读约定

本文优先使用中文。界面文字、文件栏目或系统固定名称必须保留英文时，采用“中文（英文原词）”的写法。例如，“一次完整操作（episode）”。

反引号中的英文，如 `success`，是系统需要保存的原词。操作员只需知道中文含义，不需要记忆拼写。

## 2. 正式采集前的硬性条件

### 2.1 没有记录确认，不开始正式采集

正式采集必须由采集管理员先确认以下条件：

- 本批次有唯一的任务编号；
- 已启用统一训练记录器；
- 已指定数据类型、模型、路线和数据分组；
- 系统能够保存操作前的情况、按键或控制动作、操作后的情况和结束原因；
- 每条记录结束后能够生成文件，并能被回放；
- 当前使用的仿真方式和设置值已经通过本批次检查。

截至本文编写日期，项目现有的会话回放记录器（`SessionRecorder`）主要用于人机交互（HCI）回放，统一训练记录器（`TrajectoryWriter`）仍属于待实施功能。因此：

> 如果采集管理员不能明确确认“本次数据由正式训练记录器写入”，本次操作只能标记为热身或调试，不能计入正式训练数据。

当前界面没有可靠的“正式录制中”按钮或指示灯。不要因为画面正在运动，就认为数据一定已经保存。

### 2.2 正式数据必须使用任务单指定的模式

操作员不得自行更换模型、路线、仿真方式或数据用途分组。

- 物理仿真（`physics`、`newton`、`newton_demo`）：模拟导丝受力、弯曲和碰撞；是否可用于正式数据，由采集管理员确认；
- 中心线引导（`guided`）：导丝沿预设路线移动，通常只用于演示和可达性检查，不得混入物理训练数据；
- MuJoCo（物理仿真工具）对照模式（`mujoco`）：用于旧版物理仿真或对照实验，只有任务单明确要求时才能采集；
- 自动控制（`AUTOPILOT`）：系统自动操控导丝；
- 人工手动（`MANUAL`）：操作员直接操控导丝；
- 强化学习辅助（`RL_ASSIST`）：由训练后的自动控制程序提供辅助；
- 安全保持（`SAFE_HOLD`）、碰撞制动（`COLLISION_STOP`）：系统已经限制或停止危险动作。

界面中的“模型”键可以循环切换多个模型，也包含对照模式。正式采集期间不要自行按 `M` 或“模型”按钮。

### 2.3 只能使用本批次允许的血管模型

第一版方案优先使用：

- 主动脉干（`aorta_trunk`）：低难度、单路线基础模型；
- 主动脉树（`aorta_tree`）：包含多条目标路线；
- 全身体膜（`segment_part`）：用于分支选择和路线规划；
- 外部血管病例（`case_001`）：由 VPP（血管路径规划项目）提供的血管模型。

但“界面中能打开”不等于“已经通过正式训练验收”。操作员只使用任务单列出的模型和路线。

`case_001` 的 `endpoints_24` 是零长度路线，`endpoints_25` 是入口附近的短路线，不得作为普通成功记录。除非任务单明确要求测试特殊路线，否则不要选择这两条路线。

## 3. 认识几个基础概念

| 名称 | 通俗解释 | 操作员需要做什么 |
|---|---|---|
| 血管模型（case） | 一套血管形状，例如主动脉树（`aorta_tree`） | 按任务单确认模型名称 |
| 路线（route） | 从入口到指定目标的路线，例如 `endpoint_9` | 确认路线名称，采集中途不能随意更换 |
| 一次完整操作（episode） | 从一次“重置”开始，到成功、失败或人工终止为止的一次尝试 | 每次尝试都要有明确开始和结束 |
| 记录步（step） | 系统连续记录的一个小时间片 | 不需要人工计数 |
| 单步记录（transition） | 一个时间片中的操作前状态、动作和操作后状态 | 由系统自动保存 |
| 路线进度（progress） | 当前路线完成度，通常显示为 0%～100% | 观察是否总体向前，允许因主动回撤而短时下降 |
| 恢复操作（recovery） | 从错分支、顶壁、停滞或轻度屈曲状态恢复 | 按任务要求完成停推、旋转、回撤和再推进 |
| 数据用途分组（split） | 训练组、验证组、测试组或最终留出组 | 由管理员指定，操作员不能修改 |
| 安全保护层（Safety Shield） | 独立的安全功能，会限速、停推、回撤或制动 | 不得关闭；记录它是否介入 |

需要特别区分：

- **操作成功**：到达指定目标并满足系统成功条件；
- **数据有效**：记录完整、模式正确、运动可信、结果标注正确；
- **训练可用**：数据有效，并且符合当前数据集用途。

一次碰撞失败可以是“有效的失败数据”；一次画面上到达终点但没有记录动作和状态，则不是有效训练数据。

## 4. 人员分工

### 4.1 采集管理员

负责：

- 启动采集服务、操作界面和正式记录器；
- 准备任务单、操作者匿名编号和路线清单；
- 固定血管模型、路线、数据用途分组、随机条件和仿真设置；
- 检查每次完整操作是否保存成功；
- 运行自动质量检查和回放检查；
- 决定数据是否入训练集。

### 4.2 操作员

负责：

- 按任务单操控导丝；
- 观察连接、模式、路线、风险和安全状态；
- 正确处理预警、制动和接管；
- 填写结果和异常说明；
- 不删除失败数据，不修改系统生成文件。

### 4.3 现场复核员（推荐）

正式人工数据采集时，推荐由第二人负责：

- 口头核对模型、路线和任务类型；
- 记录风险事件、接管和失败原因；
- 防止操作员在紧张操作时漏填结果；
- 每隔若干条抽查一次回放。

## 5. 认识操作界面

### 5.1 正式采集前必须看清的项目

开始前依次确认：

1. **连接状态**：显示“已连接”；
2. **控制模式**：与任务单一致，例如“手动”；
3. **模型名称**：与任务单一致；
4. **路线/分支名称**：与任务单一致；
5. **仿真方式**：与任务单一致，不能误用中心线引导（`guided`）或对照（Compare）模式；
6. **路径进度**：重置后应位于合理的起始值；
7. **安全状态**：开始时应为“待机”或“安全”；
8. **导丝位置**：导丝应从入口附近开始，不应穿壁、飞散或远离血管；
9. **记录状态**：由采集管理员确认正式记录器已经开启。

任意一项不符合，不要按推进键。

### 5.2 键盘操作

| 按键 | 当前作用 | 正式采集注意事项 |
|---|---|---|
| `W` | 推进导丝 | 建议短按或间歇按，避免持续满推进 |
| `S` | 回撤导丝 | 用于减压、脱离顶壁、错分支回撤和精细定位 |
| `A` | 向一个方向旋转 | 旋转后观察尖端方向和风险变化 |
| `D` | 向相反方向旋转 | 不要在高接触力下长时间连续旋转 |
| `R` | 重置当前一次操作 | 只有确认上一条已经结束并保存后才能使用 |
| `C` | 切换视角 | 不改变模型和路线，可按任务要求使用 |
| `M` | 切换模型 | 正式采集期间禁止自行使用 |
| `B` | 切换分支路线 | 仅在上一条已保存、任务单要求切换时使用 |
| `X` | 交换 DSA（数字减影血管影像）和 3D（三维）显示区域 | 必须记录本批次采用的屏幕模式 |
| `ESC` | 退出点击自动导航，回到手动 | 人工接管时优先使用；ESC 是键盘左上角的退出键 |

任何 `W/S/A/D` 手动输入都会取消当前点击自动导航。

### 5.3 鼠标操作

- 在 3D 区域短按路径上的位置：可能启动点击自动导航；
- 左键拖动：旋转观察视角；
- 中键拖动：平移视角；
- 滚轮：缩放视角。

采集 D2 人工成功数据（系统名称 `D2_human_success`）时，不要点击路径启动自动导航。若误启动，应立即按 `ESC` 或“接管”，结束本次操作，并注明“误用自动导航”；不要继续把它当作纯人工成功数据。

### 5.4 底部按钮

| 按钮 | 作用 | 使用规则 |
|---|---|---|
| 停止 | 紧急停止当前推进并退出自动控制 | 风险快速恶化、画面异常或无法控制时使用 |
| 恢复 | 恢复上一次点击目标的自动导航 | 只用于任务要求的自动/辅助数据 |
| 接管 | 退出自动控制，交给人工 | 策略失败后的人工纠正或安全接管时使用 |
| 视角 | 切换观察视角 | 可按任务要求使用 |
| 模型 | 切换模型 | 正式采集期间禁止自行使用 |
| 分支 | 切换路线 | 仅在两次完整操作之间按任务单切换 |
| 重置 | 重新开始一次操作 | 保存确认后才能使用 |
| 形变、调试 | 开发调试功能 | 非开发操作员不得使用 |

当前界面的“速度预设”“角度步进”和部分辅助选项仍可能只是界面占位，不一定真正改变导丝操作效果。正式采集不得依赖这些控件。

## 6. 如何看懂安全提示和路线信息

### 6.1 安全状态优先级最高

| 界面状态 | 含义 | 操作员动作 |
|---|---|---|
| 待机（`STANDBY`） | 尚未推进或等待操作 | 核对任务后再开始 |
| 安全导航（`SAFE_NAV`） | 当前可继续观察和操作 | 保持平稳节奏，不代表可以持续满推 |
| 风险预警（`DANGER_WARNING`） | 距壁、接触、偏差或其他风险升高 | 立即停止推进，观察后小幅旋转或轻回撤 |
| 碰撞制动（`COLLISION_STOP`） | 系统已经制动 | 松开全部按键，不得强行恢复；记录失败并结束本次操作 |

如果“风险颜色”和“安全状态”不一致，以更严重的一项处理。

### 6.2 风险颜色

当前界面的颜色主要参考风险分数（`risk_score`）和导丝尖端到血管壁的距离：

- 风险分数达到或超过 0.75：红色高风险；
- 风险分数在 0.35～0.75 之间：黄色中风险；
- 风险分数低于 0.35 时，再看壁距：大于 1.5 毫米为绿色，0.8～1.5 毫米为黄色，小于 0.8 毫米为红色。

这些数值只是当前仿真界面的提示规则，不是临床安全标准，也不是最终的数据录用标准。操作员应同时看颜色、数值变化趋势和安全保护层状态。

### 6.3 路线进度（progress）

正常现象：

- 总体随推进上升；
- 为了恢复或重新定位，短时间下降；
- 在弯道或旋转调整时暂时不变。

异常现象：

- 没有操作时大幅跳变；
- 导丝未移动但进度瞬间从低值跳到接近终点；
- 画面中的尖端位置和进度明显不一致；
- 重置后仍保留上一条的进度。

短时回退不是坏数据；无法解释的跳变属于技术异常。

### 6.4 接触力、离血管壁的距离和路线偏离程度

- **接触力**：应为非负值。持续上升说明顶壁、卡住或穿出血管壁的风险增加；
- **离壁距离**：指导丝尖端离血管壁还有多远。数值越小越需要谨慎，但在物理仿真中贴壁不一定等于已经穿壁；
- **路线偏离程度**：数值越小，通常表示越接近规划路线，还要结合血管粗细判断；
- **到目标的剩余距离**：应总体下降，主动回撤时可以短时上升；
- **弯曲程度**：弯道处通常会升高。如果突然出现极端值，并伴随导丝异常弹开，可能是系统计算异常。

方案没有给出可直接用于临床的接触力界限。不要自行规定“超过多少就危险”；达到任务单设定的危险界限时，以系统的预警或制动提示为准。

## 7. 每次完整操作的标准流程

### 7.1 开始前：两人核对或口头自检

逐项读出并确认：

- 任务编号；
- 操作员匿名编号，例如 `op_003`；
- 数据类型，例如 D2 人工成功（`D2_human_success`）；
- 血管模型（case）；
- 目标路线（route）；
- 数据用途分组：训练（`train`）、验证（`val`）、测试（`test`）或最终留出（`challenge_holdout`）；
- 谁在控制：人工（`human`）、自动控制（`autopilot`）、恢复操作（`recovery`）或强化学习失败后的人工纠正（`rl correction`）；
- 仿真方式和运行模式；
- 屏幕/视角模式；
- 是否允许自动导航或中心线引导叠加显示（`guided overlay`）；
- 当前尝试编号。

数据用途分组、随机条件、软件版本和仿真设置应由系统自动写入，操作员不得手工修改。

### 7.2 初始化

1. 确认上一次完整操作已保存完成；
2. 按 `R` 或“重置”；
3. 松开全部按键，等待画面稳定；
4. 检查导丝起点、进度、路线和安全状态；
5. 由采集管理员确认本条记录已开始；
6. 若初始即穿壁、爆开、明显偏离入口或处于制动状态，标记为初始化失败，不要尝试用操作把它“救回来”。

### 7.3 操作原则

推荐采用“观察—短操作—再观察”的节奏：

1. 短按推进；
2. 观察尖端方向、进度、接触力和风险；
3. 需要转向时先减小或停止推进；
4. 小幅旋转，等待尖端响应；
5. 方向稳定后再推进；
6. 风险上升时先停推，再决定旋转还是回撤。

不要为了快速完成而长时间同时满推进、满旋转。自然、可解释、可重复的推拉旋转节律比单纯追求最短时间更有训练价值。

### 7.4 结束条件

出现下列任一情况，本次操作结束：

- 系统明确显示到达目标并判定成功；
- 进入错误终末分支；
- 触发碰撞制动（`COLLISION_STOP`）；
- 严重弯折、导丝异常弹开或导丝失控；
- 长时间无进展并达到任务超时条件；
- 连接中断或画面冻结；
- 操作员或复核员决定人工终止。

进度达到约 98% 可以作为接近终点的参考，但不能仅凭进度数字自行判定成功。应以系统成功状态、目标位置和稳定保持结果为准。

### 7.5 结束后

1. 松开全部按键；
2. 不要立即按 `R`；
3. 等待记录器保存完最后一刻的信息；
4. 填写成功/失败和结束原因；
5. 记录是否发生预警、制动、安全保护层干预、自动接管或人工接管；
6. 记录异常现象和大致发生进度；
7. 等待采集管理员确认文件已经生成；
8. 确认后才能开始下一条。

## 8. 人工成功数据采集：D2

### 8.1 目标

人工成功数据用于补充自动控制缺少的人类推、拉、旋转节奏。重点不是证明操作员有多快，而是得到安全、自然、完整的成功记录。

### 8.2 采集规则

- 每位操作员先完成 5 条低难度热身；
- 热身数据明确标记为“热身”（`warmup`），不进入正式训练；
- 正式采集时，每条路线至少完成 3 次成功，或最多尝试 10 次；
- 未成功的尝试也要保存并标注原因，不能删除；
- 第一版人工成功数据总体目标为 20～50 次完整操作；
- 必须记录操作设备、屏幕模式、是否开启引导画面以及是否被安全保护层接管。

### 8.3 合格的人工成功记录

应满足：

- 全程为任务要求的人工控制，没有误用点击自动导航；
- 尖端运动连续，没有瞬移或异常弹开；
- 进度总体上升，必要的短时回撤有明确目的；
- 遇到弯道或风险时能停推、调整再推进；
- 到达正确目标；
- 没有长时间满推进顶壁；
- 结束状态、失败事件和接管事件记录完整。

如果最终成功但中途多次依赖安全保护层脱困，数据仍需保留，但应标记为“待复核”，不能直接视为高质量人工示范。

---

## 9. 恢复数据采集：D3

### 9.1 目标

恢复数据用来教训练后的自动控制程序怎样从不理想状态中脱困。它不要求从入口开始，也不要求全程无风险，但要求恢复动作正确、风险受控、事件记录完整。

恢复场景必须由采集管理员或系统初始化。操作员不得通过持续撞击血管壁来人为制造危险状态。

### 9.2 五类常见恢复任务

| 场景 | 看到的现象 | 推荐动作顺序 | 怎样算恢复成功 |
|---|---|---|---|
| 错分支 | 尖端进入非目标分支，目标进度不再合理增加 | 停推 → 回撤至分叉前 → 调整旋转 → 重新进入目标分支 | 返回正确路线并重新产生稳定进展 |
| 顶壁/高接触 | 接触力上升、壁距下降、出现预警 | 立即停推 → 小幅旋转 → 轻回撤 → 风险下降后再推进 | 接触力下降、安全状态恢复 |
| 长时间无进展 | 尖端在局部反复运动，进度长时间不变 | 停推 → 改变方向；必要时回撤 → 再推进 | 进度重新持续上升 |
| 轻度屈曲/松弛 | 中段堆积、尖端不随推进前进 | 停推 → 回撤释放松弛 → 调整旋转 → 缓慢恢复推进 | 导丝形态恢复，尖端重新响应 |
| 目标附近过冲 | 接近目标后位置超出或偏离 | 停推 → 小幅回撤 → 微调旋转和位置 | 在目标区域稳定停止 |

### 9.3 恢复数据不是失败数据的同义词

有效恢复数据至少应包含：

- 清楚的初始问题；
- 操作员采取的纠正动作；
- 风险或进度趋势发生改善；
- 恢复是否成功的明确结论。

如果只记录到“卡住”，没有后续纠正动作，它可以作为失败记录，但不能标记为成功恢复记录。

## 10. 人工纠正和留出评估

### 10.1 D4：自动控制失败后的人工纠正

当任务单要求“失败后人工纠正采集”（英文简称 DAgger，即自动控制出错后由人工示范正确做法）时：

1. 先让自动控制程序运行；
2. 观察失败迹象，例如进度停滞、风险持续升高或进入错误分支；
3. 按 `ESC` 或“接管”切换到人工；
4. 执行正确恢复动作；
5. 记录接管时刻、接管原因和纠正结果；
6. 不得把接管后的混合记录标记为纯人工或纯强化学习（RL）数据。

理想情况下，系统应保留失败前 5 秒和失败后至少 3 秒的内容。操作员只需确保接管原因记录准确。

### 10.2 D5：最终留出评估（holdout）

留出评估数据只用于评价，不得进入训练集。

- 每条指定路线至少完成 20 次评估；
- 评估期间不得临时改变路线难度、仿真设置或辅助模式；
- 不得因为结果不好而重做后删除失败记录；
- 不得提前使用评估路线进行热身；
- 人工、自动控制和强化学习的结果必须分别标记。

## 11. 风险事件的标准处置

### 11.1 黄色预警

1. 松开 `W`，停止继续推进；
2. 观察接触力、壁距和尖端方向；
3. 小幅旋转；
4. 如果风险不下降，轻按 `S` 回撤；
5. 安全状态恢复后再缓慢推进；
6. 在本次操作的备注中记录预警。

### 11.2 红色高风险或风险快速恶化

1. 立即松开全部按键；
2. 按“停止”；
3. 不要在高接触状态下持续旋转；
4. 通知复核员；
5. 等待系统稳定并完成记录；
6. 按任务要求结束或进入人工恢复。

### 11.3 碰撞制动（`COLLISION_STOP`）

1. 不再输入推进或旋转；
2. 不点击“恢复”强行继续；
3. 将结束原因标为“碰撞制动”（系统值 `collision_stop`）；
4. 记录发生时的路线、进度和可见现象；
5. 等待保存确认；
6. 由采集管理员判断是否回放、复核或重置。

碰撞失败只要记录完整，就是有价值的安全/失败数据；不要为了提高成功率删除。

### 11.4 连接中断、画面冻结或导丝爆开

1. 松开全部按键；
2. 按“停止”；
3. 记下发生时间和当前尝试序号（attempt）；
4. 标记为技术异常，不要标成普通失败；
5. 不要反复按 `R` 或切换模型；
6. 由管理员确认数据文件是否完整。

## 12. 现场如何判断数据质量

### 12.1 先判断“数据是否有效”，再判断“操作是否成功”

使用下面五问：

1. **身份对吗？** 任务、操作者、模型、路线、数据用途分组和控制来源是否正确；
2. **记录全吗？** 是否从重置后开始，直到成功或失败结束，文件是否生成；
3. **运动真实吗？** 导丝是否连续运动，没有瞬移、爆开或与输入无关的跳变；
4. **操作类型对吗？** 记录中写的人工、自动、恢复或强化学习失败后人工纠正，是否与实际操作一致；
5. **结果清楚吗？** 是否有明确的成功/失败、结束原因和异常备注。

只要有一问不能回答，就先标记“待复核”，不要直接放入正式数据集。

### 12.2 三类现场结论

| 结论 | 含义 | 例子 | 处理 |
|---|---|---|---|
| 绿色：可以进入正式数据集 | 记录完整，模式正确，运动可信，说明清楚 | 纯人工安全到达正确目标 | 进入自动质量检查 |
| 黄色：待复核 | 数据可能有价值，但有风险、接管或行为质量问题 | 触发预警后成功恢复；成功但安全保护层多次介入 | 保留并注明情况，由管理员复核 |
| 红色：技术性作废 | 记录本身不可信或任务信息错误 | 无记录文件、连接中断、错模型、误用中心线引导、回放不一致 | 不进正式数据集，可保留在问题排查区（debug） |

“红色技术性作废”和“红色高风险事件”不是一回事。一次被完整记录的高风险失败可以是有效数据；一次没有被完整记录的漂亮成功才是技术性作废。

### 12.3 可以进入正式数据集的典型表现

- 模型、路线、数据用途分组和控制来源正确；
- 记录从第 0 步开始，连续到结束；
- 操作和尖端响应关系合理；
- 路线进度（`progress`）在 0～1 范围内，总体变化可以解释；
- 风险分数（`risk_score`）在 0～1 范围内；
- 接触力（`contact_force`）不小于 0；
- 回撤时路线进度可以短时下降，但应与操作一致；
- 失败、恢复、安全保护层介入和人工接管均有记录；
- 回放能重现大致相同的导丝尖端移动过程和安全事件。

其中数值范围、记录是否连续、各类记录数量是否一致，由系统自动检查。操作员主要负责发现画面和操作中肉眼可见的不一致。

### 12.4 必须待复核的情况

- 成功但长时间满推进顶壁；
- 频繁快速来回旋转，动作缺少明确目的；
- 多次由安全保护层代替操作员脱困；
- 中途由人工切换到自动，或由自动切换到人工；
- 路线进度明显回退，但操作员无法说明原因；
- 失败原因不确定；
- 风险状态和画面表现明显不一致；
- 操作员认为自己到达目标，但系统没有判定成功。

这些记录不要删除，应保留并写清真实情况。它们可能适合分析失败或练习脱困，但不一定适合用来模仿人工成功操作。

### 12.5 必须从正式训练集排除的情况

- 没有正式记录文件；
- 缺少血管模型、路线、数据用途分组、操作员编号（`operator_id`）或结束原因；
- 任务要求人工，但误用点击自动导航；
- 任务要求物理模式，但实际使用了中心线引导（`guided`）；
- 采集中途切换模型或路线；
- 连接中断造成记录不完整，而且系统没有标明“被迫提前结束”（`truncated`）；
- 导丝瞬移、爆开、开始时已经穿出血管壁，或出现无法解释的异常抖动；
- 重置覆盖了上一条结束状态；
- 路线不在当前模型的路线清单中；
- 回放无法重现导丝尖端的移动过程或关键安全事件；
- 出现无效数值（`NaN/Inf`）、记录数量不一致或记录步不连续等自动检查错误。

技术性作废数据可以保留在问题排查区（debug，专门存放排查问题的数据），但不能通过修改分类说明把它伪装成正式数据。

## 13. 自动质量检查报告怎么看

操作员不需要运行检查程序，但应能读懂管理员给出的报告。

### 13.1 一次完整操作的常见检查项

| 报告项 | 合格含义 | 不合格时怎么做 |
|---|---|---|
| 记录步连续（step） | 从 0 到最后一步，中间没有缺步 | 技术性作废 |
| 各类记录数量一致 | 状态、动作、得分和其他信息的数量相同 | 技术性作废 |
| 无效数值（NaN/Inf） | 所有必填数字都正常 | 技术性作废 |
| 动作记录完整 | 原始控制意图、最终推进/旋转和安全层是否修改动作都有记录 | 缺失时不进入正式训练 |
| 训练得分和风险扣分明细 | 进度、接触、风险和平稳程度等项目可以分别统计；系统中称为“奖励和代价” | 缺失时不进入正式训练 |
| 路线进度范围（progress） | 始终在 0～1 | 复核或作废 |
| 回撤比例（backtrack_ratio） | 统计路线进度下降的比例，不是越低越好 | 结合任务判断；恢复数据可以较高 |
| 接触力（contact_force） | 不小于 0；高接触事件有对应安全状态 | 无安全记录则复核或作废 |
| 路线编号（route_id） | 存在于当前模型路线清单 | 修正任务信息或作废 |
| 随机条件和软件版本（seed/git_commit） | 随机条件和软件版本记录完整 | 不进入正式数据集；可保留用于排查问题 |
| 结束原因（termination_reason） | 结束原因在规定列表内 | 补充复核，不能猜测 |
| 回放检查（replay） | 回放中的导丝移动和安全事件与原记录接近 | 不一致时不进入训练 |

### 13.2 常用结束原因

| 结束原因 | 何时使用 |
|---|---|
| 成功（`success`） | 系统确认到达目标 |
| 超时（`timeout`） | 达到最大操作时间或步数 |
| 进入错误分支（`wrong_branch`） | 进入错误终末分支 |
| 碰撞制动（`collision_stop`） | 触发碰撞制动 |
| 人工终止（`manual_abort`） | 操作员或复核员主动结束 |

连接中断、初始化失败和导丝数值爆开，应作为技术异常单独记录。管理员再把它们归入系统规定的类别；操作员不要随意选择一个普通失败原因代替。

## 14. 批次级质量和数量要求

单条记录合格，不代表整个数据集已经合格。采集管理员应按以下要求组织批次，操作员需要理解为什么不能只采简单成功路线。

| 项目 | 第一版要求 |
|---|---:|
| D2 人工成功数据 | 20～50 次完整操作 |
| 每位操作员热身 | 5 条，不入训练 |
| 每条正式人工路线 | 至少 3 次成功或 10 次尝试 |
| 每条训练路线（train route） | 至少 20 次成功操作 |
| 每条验证/测试路线（val/test route） | 至少 20 次评估操作 |
| 恢复操作的单步记录占比 | 10%～25% |
| 错分支记录（wrong-branch episode） | 每个分支模型至少 20 次 |
| 最终留出评估（holdout） | 每条路线 20 次，不进训练 |
| 正式进行“模仿已有操作”的训练前，自动控制数据 | 至少 2 万条有效单步记录 |
| 正式进行“模仿已有操作”的训练前，恢复数据 | 至少 5000 条有效单步记录 |

操作员不需要人工统计单步记录数量。系统会按记录步自动统计；操作员只需按任务单完成规定的操作次数。

以下做法会造成数据集偏差：

- 只保留成功、删除失败；
- 只采最简单路线；
- 同一操作者包办全部人工数据；
- 为提高成功率反复使用中心线引导或自动导航；
- 将同一血管模型产生的多条路线随意分到不同数据用途组；
- 把零长度、近入口路线当作普通成功记录。

## 16. 每日采集建议流程

### 16.1 开始采集前

1. 管理员完成系统和记录器检查；
2. 操作员阅读当日任务单；
3. 检查键盘、鼠标、显示器和网络；
4. 每位操作员完成 5 条热身；
5. 用 1 条短路线做小规模试采（smoke，系统文档中也可能称为“冒烟检查”）；
6. 管理员确认该条能保存、通过基础质量检查并回放；
7. 通过后开始批量采集。

### 16.2 采集中

- 每完成 5～10 条，暂停一次；
- 核对文件数量和尝试次数；
- 抽查至少 1 条成功和 1 条失败/恢复回放；
- 检查是否出现同一种失败持续增加；
- 操作员疲劳、误按键增加或反应变慢时停止采集。

### 16.3 当日结束

1. 确认所有完整操作均有结果和结束原因；
2. 核对成功数、失败数、技术异常数；
3. 核对模型和路线覆盖情况；
4. 列出所有待复核记录；
5. 管理员生成当日质量检查报告（QC）和路线覆盖报告（route coverage）；
6. 对至少一条风险事件进行回放；
7. 数据完成备份后再关闭系统。

## 17. 常见错误与处理

### 17.1 忘记确认记录器就开始操作

立即停止。本条只能作为调试记录；不要事后补写操作编号（`episode_id`），假装它是正式记录。

### 17.2 按错 `M`，模型发生变化

立即结束本次操作，标记为技术性作废。重新核对任务后再开始一次新的操作。

### 17.3 按错 `B`，路线发生变化

不要继续。标记路线切换异常，等待管理员确认上一条是否完整。

### 17.4 人工数据中误点路径，启动了自动导航

按 `ESC` 或“接管”并结束本次操作，注明“自动导航曾介入”。这条记录不能放入纯人工成功数据中，但可由管理员判断是否作为接管数据保留。

### 17.5 操作失败，是否需要删除重做

不需要。保存失败并标注原因，然后按任务单决定是否继续尝试。失败数据是恢复学习和安全分析的重要组成部分。

### 17.6 路线进度下降，是否代表坏数据

不一定。主动回撤、错分支恢复和目标附近微调都会造成合理回退。只有无法解释的跳变才是异常。

### 17.7 到达终点但系统没有显示“成功”

不要自行改成成功。标记“待复核”，保存回放，由管理员检查目标判定和终止条件。

### 17.8 触发制动后点击“恢复”又继续成功

原碰撞事件仍必须保留。若任务没有明确要求制动恢复，该条不能作为普通成功示范。

- [ ] 任务编号、操作员编号（operator_id，系统中的操作员代号）已确认

## 19. 培训通过建议

非开发操作员开始正式采集前，建议完成以下考核：

1. 能说清一次完整操作、路线、路线进度、恢复操作和数据用途分组的含义；
2. 能在不看提示的情况下正确使用 `W/S/A/D/R/ESC`；
3. 能辨认待机、安全、预警和碰撞制动；
4. 能演示一次黄色预警下的停推、旋转、轻回撤；
5. 能正确区分“有效失败数据”和“技术性作废数据”；
6. 能完整填写一张操作记录表；
7. 能在回放中指出一次成功、一次合理回撤和一次风险事件；
8. 连续完成 5 条低难度热身，且无误切模型、路线或模式。

培训通过只代表可以执行采集任务，不代表可以自行修改任务设置、仿真设置或数据分类规则。

## 20. 关键原则总结

1. **没有正式记录确认，不开始采集。**
2. **任务单指定什么模型、路线和模式，就只使用什么。**
3. **先停推，再处理风险。**
4. **失败可以是好数据，缺记录一定不是好数据。**
5. **不删除失败，不隐瞒接管，不把自动数据标成人工。**
6. **结束后先保存和标注，再重置。**
7. **看不懂或不确定时标记待复核，不猜测、不补造。**
