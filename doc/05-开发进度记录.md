### 2.5 CathSim NavigationEngine 桥接

新增后端模块：

| 文件 | 作用 |
|------|------|
| `services/navigation_engine.py` | 封装 CathSim MuJoCo 环境，提供 `reset()`/`step()` |
| `services/session_manager.py` | 多会话管理，支持并发导航实例 |

`NavigationEngine` 核心功能：

- 封装 `cathsim.dm.make_dm_env` 创建环境
- `reset()` 返回 `NavigationState` 初始状态
- `step(delta_push, delta_rotate)` 执行物理仿真步
- `get_safety_status(state)` 返回安全级别
- 提取标准化状态字段：
  - `tip_position` - 导丝头端位置
  - `tip_direction` - 导丝头端方向向量
  - `velocity` - 头端速度
  - `contact_force` - 接触力
  - `episode_length` - 当前 episode 步数
  - `target_position` - 目标位置
  - `reward` / `done` - 强化学习信号

`SessionManager` 核心功能：

- 线程安全的会话创建/销毁
- 自动过期清理（默认 1 小时）
- 最大并发会话限制（默认 10）
- 会话元数据跟踪（创建时间、步数、episode 数）

### 2.10 B-spline 路径平滑

更新 `services/path_planner.py`：

- `smooth_path()` 方法：基于 scipy.interpolate.splprep 的 B-spline 平滑
- `_compute_max_curvature()` 方法：计算路径最大曲率
- `PathResult` 增加字段：`smooth_waypoints`, `smooth_length_mm`, `max_curvature`
- `plan()` 方法支持 `smooth` 参数

平滑算法特性：

- 基于累积弧长参数化
- 支持可调平滑因子 `smoothing_factor`（0.0 = 插值，>0 = 平滑）
- 自动计算输出点数（默认 2x 输入）
- 计算路径曲率用于安全评估

API 更新：

| 方法 | 路径 | 新增参数 |
|------|------|----------|
| `POST` | `/api/v1/path/plan` | `smooth: bool` |

响应新增字段：

- `smooth_waypoints` - 平滑后的路径点
- `smooth_length_mm` - 平滑路径长度
- `max_curvature` - 最大曲率 (mm⁻¹)

### 10.3 关键实现说明

1. **wall_distance（壁面距离代理）**
   - 从 `physics.data.contact.dist` 读取接触间隙，惩罚穿透（clip 到 0），无接触时返回哨兵值 `MAX_WALL_DISTANCE = 0.05m`
   - 已知局限：当前为「接触即贴壁」的粗粒度代理，DANGER 带较窄；后续可替换为精确几何最近点查询

2. **curvature（曲率）**
   - 基于最近 3 个尖端位置的 Menger 曲率（外接圆半径倒数），单位 m⁻¹
   - 历史不足 3 点、共线或重合时返回 0

3. **path_progress / path_deviation**
   - `planned_path` 为 MuJoCo 米制坐标点列；构建 `scipy.spatial.cKDTree`
   - progress = 最近路径顶点的累积弧长 / 总弧长，范围 [0, 1]
   - deviation = 到最近顶点欧氏距离（米）
   - `planned_path` 可选，为 `None` 时返回 (0, 0)，向下兼容

4. **tip_quaternion**
   - 从尖端 body 的 `physics.data.xquat` 读取，MuJoCo `[w,x,y,z]` 重排为协议约定的 `[x,y,z,w]`
   - 读取失败回退单位四元数

5. **safety_status 状态机**（按 `01-总体技术方案.md §五`）

   | 条件 | 状态 |
   |------|------|
   | episode_length == 0 | STANDBY |

   | 0.0005m ≤ wall_distance < 0.001m | DANGER_WARNING |
   | wall_distance < 0.0005m | COLLISION_STOP |

### 13.1 当前结论

导丝在可见的 low_tort 体模内**流畅推进/后退/转向**，连接稳定、控制无积压延迟。

```text

  -> 后端线程池执行 MuJoCo step（事件循环不阻塞、心跳稳定）
```

### 13.2 问题链与根因（按定位顺序）

### 14.4 关键实现说明

1. **进给轴校准**：low_tort 默认体模下，正向 push 25 步实测尖端位移方向 `[0.072, 0.997, -0.027] ≈ +y`，

2. **入口四元数**：`quat_from_vectors(a, b)` 返回把 a 旋到 b 的 MuJoCo `[w,x,y,z]` 四元数，

### 15.2 设计要点

1. **零后端 / 零协议改动**：第三人称与第一人称所需的 `tip.position` / `tip.direction`
   / `tip.quaternion` 在阶段七已进 `state_batch`，客户端直接复用。

3. **三模式职责分离**：
   - `OVERVIEW`：保留原整血管 AABB 框定（main_controller 拥有，全局空间）。
   - `FOLLOW`：相机位 = `tip − dir·follow_back + UP·follow_height`，`look_at(tip)`；

   - `ENDOSCOPE`：相机位 = `tip − dir·2mm`（略后退避免穿模），沿 `direction` 看血管前方，

4. **退化保护**：`update_tip` 忽略零向量 `direction` / 零四元数（STANDBY 期保留上一帧朝向）；
   `_safe_up()` 保证 look_at 的 up 向量不与前向平行。

5. **自动切入**：首帧 tip 到达后自动从 OVERVIEW 切到 FOLLOW，操作者无需手动即看到导丝近景；
   之后 `C` 键循环三模式，HUD 显示当前视角名。

## 十七、阶段十三执行记录：VPP 全程导航——运动学循路模式（guided）

### 17.1 根因定位（推翻"渲染对齐"假设）

阶段十二加入绿色入口标记后，实机现象变为"导丝能到入口附近、但无论推/转都到不了目标"。
逐项排查，用客户端真实参数（`case_001_vpp`，n_bodies=40，start=Endpoints-24→end=Endpoints-1）跑后端实测：

| 项 | 值 | 结论 |
|----|----|------|
| 两 GLB 节点变换 | 单位阵；顶点为原始物理坐标 | **排除轴向/渲染错位**；导丝/入口/血管同帧 |
| 导丝长度（n_bodies=40） | **82 mm** | 远短于血管 |
| slider 插入行程硬上限 | **200 mm**（`range=[0,0.2]`）| 远短于路径 |
| VPP 规划路径长度 | **1136 mm** | — |
| 纯推进实测 | 第一个弯**屈曲顶墙**，slider 卡在 ~36mm、进度 4.3%、接触力饱和 5N | 物理上**到不了** |

**根因**：CathSim 导丝模型是为 ~150mm 小主动脉体模（low_tort/phantom3）设计的；放进完整 VPP 血管
（路径 1.1m），"82mm 导丝 + 200mm 行程"既会在首个弯屈曲卡死，几何上也根本够不着远端目标。
low_tort 实机正常正是因为它在原点附近且尺度匹配（阶段九已验证），而 VPP 全程导航**从未实机验证过**（§14.9 为 TODO）。

### 17.2 解决方案：运动学循路模式（guided）

经确认（用户选择"完整真实导丝 + 自动循路"），鉴于在 235 凸包血管内模拟 ~700 节长导丝在交互帧率下不可行，
采用**后端运动学循路**：导丝沿规划中心线由"插入深度"参数驱动，绕过 MuJoCo 物理，保证从入口一路可达目标。

```text
guided + planned_path
  -> reset(): s=0，tip 落在 path[0]（入口）
  -> step(push): s = clip(s + push·advance_per_step, 0, total_len)
  -> tip = 路径弧长 s 处插值；direction = 该处切线
  -> get_render_bodies(): 沿 [s-wire_length, s] 采样中心线为导丝体
  -> path_progress = s/total_len（必达 1.0）；deviation = 0
```

物理模式（low_tort 等短体模、无 planned_path）完全保持不变，向下兼容。

### 17.3 修改内容

| 文件 | 改动 |
|------|------|
| `services/navigation_engine.py` | `NavigationEngine` 新增 `guided`/`advance_per_step`/`wire_length` 参数与 `_s` 插入深度；新增 `_is_guided`/`_point_at_arclen`/`_tangent_at_arclen`/`_quat_from_direction`/`_guided_state`/`_guided_render_bodies`；`reset`/`step`/`get_render_bodies` 增加 guided 分支；`_compute_velocity` 兼容无 MuJoCo 环境 |
| `services/session_manager.py` | `create_session` 新增 `guided` 透传 |
| `services/websocket_handler.py` | `SessionStartData` 新增 `guided`；`_handle_session_start` 对 `*_vpp` + 已规划路径**自动启用** guided |
| `godot_client/scripts/websocket_client.gd` | 新增 `@export guided=true`，`session_start` 带 `guided`（仅在有路径时生效，low_tort 不受影响）|

### 17.4 关键设计说明

1. **自动启用**：`guided = params.guided or (planned_path and phantom 以 _vpp 结尾)`——VPP 路由开箱即用，客户端无需额外配置；low_tort 无路径时 `_is_guided()` 恒 False，仍走物理。
2. **绿色入口标记即真值**：guided 下 reset tip 精确落在 `path[0]`，与阶段十二的入口标记完全重合（实测 dist=0）。
3. **可正可负**：`push>0` 进、`push<0` 退；`s` 夹在 `[0, total_len]`，progress 到 1.0 即 `done=True`，尖端停在目标。
4. **无 MuJoCo 开销**：guided 会话不加载 235 凸包 phantom，无 ~17s 冷启动、无 28ms/步物理；瞬时、确定、必达。

## 十八、阶段十四：导丝物理化外观（方案评审与决策）

### 18.1 问题反馈（实机）

guided 循路模式虽能到达目标，但物理形态缺失：

1. 跟随模式下导丝呈**锯齿状**——guided 只发抽象路径点、且客户端渲染为无粗细细线，且只显示尖端最后 12cm。
2. 只按规划路径**简单移动**，忽略真实物理：导丝进入血管会弯曲、会碰壁，转弯处看不到导丝弯曲曲折。

### 18.2 根本张力

在完整 1.1m VPP 血管里跑**真实 MuJoCo 物理本质上很难**：CathSim 导丝模型为 ~150mm 小体模设计、
slider 直线进给在第一个弯（~36mm 处）就屈曲卡死；要走完 1.1m 需数百节导丝 → 交互帧率崩溃，且不保证调得通。
故"完全真实物理"与"可靠流畅"在当前模型下不可兼得。

### 18.3 三方案

| 方案 | 做法 | 真实度 | 可靠/性能 | 风险 |
|------|------|--------|-----------|------|
| A 循路+物理化外观 | guided 可靠到达 + ①整条已插入导丝渲染成平滑管状(消锯齿) ②全长显示随每个弯曲折 ③转弯处贴向内壁 | 视觉真实(弯曲贴壁随血管曲折) | 高、流畅 | 低 |
| B 真实物理导丝 | 加长导丝+延长行程+中心线吸引力辅助，MuJoCo 真实弯曲/碰壁 | 物理真实(含接触力) | 帧率大降、可能走不完整 | 高、不保证 |
| C 分场景双模式 | 短体模物理训练 / 长 VPP 用 A，HUD 标注可切换 | 按场景 | 中 | 中 |

### 18.4 决策

采用 **方案 A（循路 + 物理化外观）**（用户确认）。在 §十九 记录实现。
方案 B/C 作为后续可选增强保留：若后续需要真实接触力训练，再单独立项做长导丝 + 解算优化与双模式切换。

## 十九、阶段十四执行记录：导丝物理化外观（方案 A）

### 19.1 当前结论

在 guided 循路基础上，让导丝在视觉上成为一根**平滑、弯曲、贴内壁、随血管全长曲折**的真实导丝，
同时保持循路的可靠到达与流畅帧率。三处改动对应三个反馈点：

```text
后端 _guided_render_bodies()
  -> 采样整条已插入导丝（entry s=0 -> tip s）        # 全长显示，随每个弯曲折
  -> 每点按局部曲率向内侧偏移（_inner_wall_offset）   # 转弯贴内壁
客户端 guidewire_renderer.gd
  -> 平行传输坐标架挤出圆环管(ImmediateMesh 三角面)   # 消锯齿、有粗细
  -> 受光金属材质                                     # 曲率经明暗可见
```

### 19.2 修改内容

| 文件 | 改动 |
|------|------|
| `services/navigation_engine.py` | `_guided_render_bodies` 改为采样 **entry→tip 全长**（~4mm 间距，上限 256 点）；新增 `_inner_wall_offset(s)`——向局部曲率中心（凹侧）偏移、仅取横向分量（端点单边差分的切向伪偏移被投影掉）、随曲率增长并夹在 `wall_lean`；`NavigationEngine` 新增 `wall_lean`（默认 2.5mm）参数 |
| `godot_client/scripts/guidewire_renderer.gd` | 导丝由细线改为**管状网格**：平行传输坐标架沿折线挤出 8 边圆环、生成三角面与法线；受光金属材质（`metallic=0.6`/`roughness=0.35`/双面），曲率经明暗显现；保留尖端球 |

### 19.3 关键实现说明

1. **全长显示**：`s_tip` 处按 ~4mm 间距从 0 采样到 tip，导丝随路径在每个弯处曲折；点数随插入深度增长、上限 256，带宽可控（每帧 ≤ ~5KB）。
2. **贴内壁**：用 `s±10mm` 三点估局部凹向，**投影掉切向分量**只留横向，故直段与端点零偏移、仅真实弯曲处向内壁靠，幅度随曲率增长并夹在 `wall_lean`（2.5mm），不会穿出管腔。
3. **消锯齿**：管状网格用平行传输坐标架避免扭转；受光材质让弯曲经明暗可见，区别于原 unshaded 细线"锯齿/涂鸦"观感。
4. **物理模式同样受益**：low_tort 物理会话的 `bodies`（MuJoCo geom）也走同一管状渲染，导丝更立体。

## 二十一、阶段十六执行记录：B-spline 平滑实际生效

### 21.1 问题

路径轨迹显示为**锯齿状**。排查发现：B-spline 平滑（`PathPlanner.smooth_path`，scipy `splprep`/`splev`）早已实现并接入下发链路（`smooth_waypoints or waypoints`），但**调用时未传 `smooth_factor`**，落到默认值 `0.0`。`smoothing_factor=0.0` 走 `s=0` 的**插值样条**分支，曲线被强制精确穿过 A\* 在 10561 节点稠密图上选出的每一个抖动节点——点变多但仍逐点穿过噪声节点，视觉上依旧锯齿。

### 21.2 修复

把 `smooth_factor` 贯通到两条规划链路并给一个真正消锯齿的默认值 `0.5`（`s = smooth_factor × n_points`，逼近样条）：

| 文件 | 改动 |
|------|------|
| `services/websocket_handler.py` | `SessionStartData` / `PathRequestData` 新增 `smooth_factor`（默认 0.5）；`_resolve_session_path`、`_handle_path_request` 透传给 `planner.plan()` |
| `services/schemas.py` | REST `PlanPathRequest` 新增 `smooth_factor`（默认 0.5） |
| `services/main.py` | `/api/v1/path/plan` 透传 `smooth_factor` |

底层 `path_planner.plan()` / `smooth_path()` 本就支持该参数，无需改算法。

### 21.3 验收

```powershell
python -m pytest tests/test_vpp_path_planner.py tests/test_services_api.py tests/test_websocket.py -m "not slow" -q
```

结果：**24 passed**（无回归）。

真实 VPP 路线（782 个 A\* 节点）平滑前后对比：

| 配置 | 平均转折角 | 最大曲率 (mm⁻¹) |
|------|-----------|----------------|
| 旧默认 `s=0.0`（插值，穿过每个抖动节点） | 5.32° | 1.881 |
| 新默认 `s=0.5`（逼近平滑） | 0.20° | 0.034 |

转折角降到约 1/26，几何上从锯齿折线变为顺滑曲线。

### 21.4 可调参数

- `smooth_factor`（默认 0.5）：残差 RMS 偏离 ≈ `sqrt(smooth_factor)` mm。细小血管担心贴壁调到 0.2~0.3；想更顺滑调到 1.0~2.0。客户端 `session_start` / `path_request` 消息可带 `smooth_factor` 覆盖默认。

### 25.3 切换流程

```text
M 键 → _cycle_model()
  → _apply_model_config(MODELS[i])        # 应用 phantom/target/case_id/start/end

  → ws.restart_session(...)                # 发 session_stop，清 session_id，_process 自动重发 session_start
```

  先 `queue_free` 旧血管及其下挂的导丝/路径/入口/相机装备，避免叠加与坐标错配。
- WebSocket 在**同一连接**上切换：`restart_session` 发 `session_stop` 后清空 `session_id`，

  后端在同连接消息顺序中先处理 stop 再处理 start，且 `session_stop` 会关旧会话释放并发额度。

### 25.7 切换渲染修复（导丝跑到血管外）

实机切换模型时,导丝出现在新血管模型外面。定位为**握手空窗期的残留帧**,

- 旧会话最后推送的 `state_batch` 携带**旧 phantom 坐标**仍在接收缓冲区;
- 切换重建出空导丝后,该残留帧被**新导丝**渲染进**新血管帧** → 导丝落在新血管外;
- 新会话(guided / low_tort)需等操作者按 W 才推下一帧,故错位**长期停留**而非一闪。

| `godot_client/scripts/websocket_client.gd` | `state_update` / `state_batch`：`session_id == ""` 时直接丢弃。`restart_session` 清空 `session_id` 到新 `session_started` 之间的旧帧全部不渲染 |
| `godot_client/scripts/guidewire_renderer.gd` | 新增 `_has_data` + 初始 `visible=false`；首个流入位置(`update_from_state` / `update_from_batch`)到达才显示,避免新建导丝默认原点(0,0,0)在离原点约 1m 的 VPP/segment_part 外闪现 |

### 26.3 技术实现细节

**Step 3 DFS 分支分割**（核心算法）：

```python
def dfs(current, parent=None):
    path = [current]
    while True:
        neighbors = [n for n in G[current] if n != parent and n not visited]
        if not neighbors:
            break  # 末端
        if len(neighbors) > 1:
            # 分岔点：递归各子分支
            for nb in neighbors:
                dfs(nb, current)
            break
        current = neighbors[0]
        path.append(current)
    return path
```

结果：完全遍历所有骨架体素（`len(visited) ≈ 2043`），无重叠。

**Step 4 B-spline 参数调优**：

- `smoothing_factor=0.25e-6`：在米制单位下对应约 0.1mm 的松弛度
  （原 VPP 用 0.5，这里降低以适应细血管的陡峭弯折）
- `degree=3`：三次样条，保留拐点同时平滑尖刺
- `num_points=downsample_pts*2`：足够密集，无可见段差

```python
# services/navigation_engine.py

def _load_phantom_graph(self) -> dict | None:
    """加载 phantom 的 graph.json (若存在)"""
    graph_path = self.phantom_assets / "meshes" / self.phantom / "graph.json"
    return json.loads(graph_path.read_text()) if graph_path.is_file() else None

def plan_to_target(self, start_pos, end_pos):
    """通过图规划任意两点间的路径（A* + B-spline）"""
    graph = self._load_phantom_graph()
    if not graph:
        return None
    planner = PathPlanner()
    planner._graph = graph
    planner._nodes = [tuple(map(float, key.split(","))) for key in graph.keys()]
    result = planner.plan(start_pos, end_pos, smooth=True, smooth_factor=0.25e-6)
    self.set_planned_path(result.smooth_waypoints or result.waypoints)
    return result.smooth_waypoints, result.smooth_length_mm / 1000.0
```

## 二十八、物理推进攻关：闭环转向 + 中心线预穿线，定位到管腔密封硬卡点

> 目标：让 `segment_part` 这类细长扭曲血管在前端看到**真物理仿真**导丝，而不是 guided 运动学循线。
> 本阶段逐层突破并把根因钉死，产出三件可复用能力，并发现下一步所需的数据。

### 28.1 为什么前端看到的不是物理仿真

`websocket_handler._handle_session_start` 中，只要 phantom 自带内建中心线（`_builtin_phantom_centerline` 非空，`segment_part` 命中）或 VPP 有规划路径，`guided` 就被强制为 `True`，且是 `or` 逻辑——**客户端即使显式发 `guided:false` 也会被覆盖**。guided 模式下 `NavigationEngine.get_render_bodies()` 走 `_guided_render_bodies()`，沿中心线按弧长合成导丝点位，根本不读 MuJoCo 物理几何。所以 `segment_part` 当前被锁死在运动学循线。

### 28.2 开环物理推进实测：必须主动转向

`segment_part` 物理推进开环实测：

- `push=1.0`：导丝在入口弯处顶住打弯、力飙到 ~5，只到 34mm/584mm。
- `push=0.15`（温和）：力降到 ~0.77，但**前进量为零**——预弯 J-tip 指向固定（错误）方位，扎进血管壁兜里，越推越盘。

结论：被动壁面引导无法穿行，**必须主动旋转 J-tip 转向**。

### 28.3 产出一：PhysicsAutopilot 闭环转向控制器

`services/physics_autopilot.py`（+ `tests/test_physics_autopilot.py`，6 passed）：

- look-ahead 取中心线前瞻点，算 tip 朝向误差；
- J-tip 方位不可观测 → 对 rotate 做**爬山式符号搜索**（误差降则保持、升则反向）；
- push 按对齐度门控、再按接触力衰减；
- stall（弧长无增益）时旋转扫掠找开口，深陷时短暂回拉。

单测证明控制逻辑（对准/调速/限力/卡死）在合成路径上正确。但 `segment_part` 实测仍只到 21mm——**说明卡点不在控制器**。

### 28.4 产出二：沿中心线预穿线 IK

诊断导丝关节布局：每节 body 经 `J0_i`(qpos 2i, x轴) / `J1_i`(qpos 2i+1, y轴) 两个铰链构成 2-DOF 万向节，子节在父系 `[0,0,seg_len]`，即段方向 = body 局部 +z。

据此实现 `NavigationEngine._thread_physics_along_path`（`prethread` 开关，默认关）：reset 时 base→tip 逐节解析反解两个铰链角，使每节 +z 对齐对应弧长处中心线切向；并把 slider 推进**一个导丝长度**让基座落到入口。

验证：离线 FK 自洽 2.3mm；MuJoCo 落位**全节 <1.3mm**。导丝可精确"长"在血管腔里。

### 28.5 钉死的硬卡点：V-HACD 凸包管腔封不住导丝

预穿线把导丝准确放进腔内，但**待不住**：

- 刚度大 → 弹直顶出，settle 后 dev 164mm；
- 刚度小 → 重力塌出，dev 234mm、force→0。

根因确认：`segment_part` 碰撞体是 **125 个 V-HACD 凸包**（血管表面分解）。凸包拼不出密封的细长管腔——鼓进腔内或留缝，管壁根本接不住/导不动导丝。

卡点全链路：插入行程上限（已参数化解决）→ 短导丝+直线 slider（预穿线绕过放置）→ **管腔碰撞不密封（真正的墙）**。

### 28.6 产出三：诊断工具 + 参数贯通

- `tools/measure_physics_reach.py`：物理推进里程测量，支持 `--autopilot` / `--prethread` / `--settle` / `--stiffness-scale`。
- `tools/inspect_guidewire_joints.py`：导丝关节/qpos 布局与世界系朝向导出。
- `insertion_max` / `stiffness_scale` 贯通 guidewire/env/NavigationEngine。
- 全部新能力默认关闭，回归 37 passed。

### 28.7 数据发现：主动脉中心线带半径，是 segment_part 的母数据

读取 `E:\下载\主动脉中心线`（3D Slicer + VMTK，LPS/mm）：30 条中心线 / 1757 控制点 / 18 endpoints + 表面 VTK + 分割 NRRD + 源 CT。

关键：**每个控制点带半径**（2.1–13.1mm，中位 4.4mm）——正是做密封管腔缺的那个量。且与 `segment_part` **同一世界坐标系**（入口点与 Endpoints-11/1000 几乎重合，waypoint→最近主动脉点中位 5.4mm），即 `segment_part` 是这份主动脉数据的子段，只是建管线时丢了半径。

### 28.8 下一步：用半径生成水密管腔（先导靶 = 主动脉本干 Curve 10）

主动脉本干锁定为 **Curve (10)**（242 点、259mm、平均半径 10.2mm，最粗最长，末端接 segment_part 入口）。计划：

1. `tools/build_tube_phantom.py`：读 Curve(10)→重采样+半径插值→沿中心线放样圆环生成**水密管腔网格**。
2. 对干净管做凸分解（区别于脏网格 V-HACD）。
3. 生成 `aorta_trunk` phantom（XML + meshes + 带半径 centerline.json + entry/target）。
4. **关键验收**：`measure_physics_reach --prethread --settle`，看预穿线导丝是否被管壁接住（dev 维持几 mm 而非 164mm）。
5. 接住后加 autopilot 测真实推进里程；成功后推广，并用半径回攻 `segment_part`。

选择粗大主动脉本干（腔径中位 8.8mm）作先导靶，是因其物理上最宽容，便于先验证"密封管腔→预穿线被接住→autopilot 推进"整套栈是否成立，再去啃细管。

### 28.9 落地结果：密封管腔成立，物理推进打通到 72%

**数据导入**：`E:\下载\主动脉中心线`（3D Slicer + VMTK）轻量源数据导入 `data/aorta_centerline/`（30 条 `.mrk.json` + endpoints + 表面 VTK + 分割 NRRD，跳过 305MB 源 CT）。`data/` 按项目约定 gitignore，源数据留在工作区供生成器读取、不入库；派生的 phantom 资产入库。

**生成器** `tools/build_tube_phantom.py`：读带半径的 Slicer 中心线 → LPS mm/1000（无翻转，与 VPP 管线一致）→ 按弧长重采样+半径插值 → **旋转最小化标架**(double-reflection) 放样 → 把环形管壁按"轴向段×角向扇区"切成**确定性凸六面体壁砖**。相邻砖共享顶点 → 并集水密、密封管腔；每砖凸 → MuJoCo 原生 mesh 几何，**不用 V-HACD**（V-HACD 正是上一阶段封不住管腔的元凶）。

**aorta_trunk phantom**：Curve(10) → 66 环(4mm)×8 扇区 = **520 块壁砖** + 不碰撞 visual + 带半径 centerline.json。已在 `NavigationEngine.VALID_PHANTOMS` 注册。

**关键修复**：visual 几何必须设 `contype=0 conaffinity=0`——否则 MuJoCo 取其凸包（填满整条弯管的实心 blob）把导丝从内部顶出（首测 dev 136mm、force=0 即穿透 blob）。修后碰撞只走密封壁砖。

**验收结果**：
- **密封管腔接住导丝**（核心里程碑）：预穿线 spawn dev 0.4–0.8mm；settle 80 步后 **dev 5.8mm、force 0.023**——导丝被真实物理管壁约束在腔内，不再弹出/塌出。对比 segment_part 的 164mm/234mm，**上一阶段的硬卡点已突破**。
- **物理推进打通**：加 autopilot 后导丝在真实物理里推进到 **max_progress 0.722（185/256mm，72%）**，最近距目标 78.7mm。
- **待解**：autopilot 在宽管腔偏猛——progress 振荡、dev 飙到 110mm、COLLISION_STOP(force 5.8)；降 base_push 到 0.12 仍甩打。根因：宽腔里 0.16m 长导丝横向约束不足、近端直段整根屈曲/回退 + stall 回拉策略过激。属控制器层（非模型层）的独立调参迭代。

**结论**：研究性卡点（密封管腔能否接住导丝）已证实可行，整套栈"半径中心线→密封壁砖→预穿线被接住→物理推进"成立。下一步为 **autopilot 宽管腔调参**（抗屈曲/降增益/收敛 stall 策略），再推广到分支树并用半径回攻 segment_part 细管。
