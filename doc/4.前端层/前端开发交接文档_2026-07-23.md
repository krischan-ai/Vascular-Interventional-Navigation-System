## 2. 当前系统主链路

```text
Godot 前端
  → WebSocket / FastAPI
  → SessionManager
  → NavigationEngine
  → ShapeIntent / PhysicsEngine
  → NewtonEngine / MuJoCoEngine / KinematicEngine
  → state_update / state_batch
  → Godot HUD 与三维渲染
```

需要始终区分：

- `NewtonEngine`：当前主要的高保真 GPU 物理路线。
- `MuJoCoEngine`：兼容原始 CathSim、物理比较和回归用途。
- `KinematicEngine` / `guided`：沿中心线的运动学演示，不等于真实力学仿真。
- 当前界面显示的“设备就绪”表示仿真会话及物理引擎就绪，不表示真实机器人硬件已经握手连接。

### 3.4 后端权威急停闭环

已新增 WebSocket 消息：

```text
emergency_stop
emergency_stop_confirmed
resume
resume_confirmed
control_rejected
control_config
```

后端行为：

- `SessionManager` 保存会话级 `emergency_stop_latched`。
- 急停时解除已启用的 ShapeIntent 自动导航。
- 锁存期间拒绝所有非零 `control`。
- 中性控制帧不会让已解除的 ShapeIntent 继续推进。
- 锁存期间拒绝启用 ShapeIntent、切换分支和重置。
- `resume` 只解除锁存，不会恢复旧的自动导航目标或重放旧控制。
- 急停和恢复均为后端确认后才改变前端最终状态。

前端行为：

- 点击急停后立即在本地门控键盘、鼠标、运动按钮和自动导航，但只显示“急停请求中”。
- 收到 `emergency_stop_confirmed` 后显示“已急停”，并记录“急停已由后端锁存”。
- 点击恢复后显示“恢复请求中”，继续保持控制禁用。
- 收到 `resume_confirmed` 后恢复手动控制，并显示绿色“后端确认：控制已恢复”。
- 连接中断后如果用户急停意图仍然存在，新会话建立后会重新向后端锁存急停，避免重连绕过急停。

主要文件：

- `services/session_manager.py`
- `services/websocket_handler.py`
- `godot_client/scripts/websocket_client.gd`
- `godot_client/scripts/main_controller.gd`

### 3.6 连接、会话和物理引擎状态

前端已经区分：

```text
connecting       正在连接
reconnecting     正在重连
socket_open      网络已连接，等待会话
initializing     后端会话/物理引擎正在初始化
session_failed   会话创建失败
ready            网络、会话和仿真设备均已就绪
disconnected     未连接
```

已完成：

- WebSocket 打开但会话未建立时不再显示“机器人已连接”。
- 底部连接面板分别显示网络、后端会话、引擎、模式和仿真设备状态。
- 会话冷启动较慢时持续显示“正在初始化”。
- 断线后按指数退避创建新的 `WebSocketPeer`。
- 重连成功后自动重新发送 `session_start`。
- `state_update/state_batch` 按后端 session ID 过滤，旧会话帧不会进入新模型。
- 会话失败后按间隔重试，但普通控制参数错误不会误标成会话失败。

当前“仿真设备就绪”不代表物理机器人已连接。真实设备通信协议和硬件心跳仍是后续任务。

- 不覆盖其他开发者或用户的本地改动。
- 不使用 `git reset --hard` 或无确认的还原命令。

### 9.2 数据可信性

- 后端缺失数据必须显示 `— / unknown / stale`。
- 不得用风险分数推算接触力。
- 不得使用固定数字假装实时数据。
- 安全状态只由后端 `data.safety` 决定。
- 空 `risk_regions` 必须保持空，不在前端补造风险体积。
- `guided` 只能描述为运动学演示，不能描述为力学仿真。

### 9.3 安全控制

- 急停状态以服务端锁存为权威。
- 前端必须先本地门控，再等待服务端确认。
- 恢复确认不能自动重启旧的 ShapeIntent。
- 任何新增控制入口都必须同时受 `_controls_blocked` 和后端锁存约束。
- 任何会引起模型运动或会话重建的操作，都要检查急停状态。

### 9.4 冻结范围

- 不修改 DSA 面板。
- 不修改 RL训练面板。
- 不修改数据采集与回放面板。
- 如果新功能不可避免地影响冻结面板，必须先向用户说明并获得确认。

### 9.5 验证口径

- “代码存在”不等于“系统已运行验证”。
- 每次功能修改至少完成相关 pytest、Godot脚本校验和本地实际运行。
- 对物理、设备和安全能力必须说明数据来源和验证边界。
- 截图必须来自当前内层 Godot 项目和本地后端，不能引用旧外层项目画面。
