# 介入导丝大曲率转弯流程引导设计方案

## 一、设计目标

本流程用于介入手术术前—术中仿真训练，目标是把临床医生通过大曲率弯道的经验，转化为系统里的可操作流程、可视化引导、物理仿真机制和训练评分指标。

临床核心逻辑是：

> 不是把导丝从 root 端硬推过去，而是“头端塑形选路 → 近端旋转定向 → 导管系统支撑 → 小步推拉试探 → 软头贴壁滑入 → 失败后换策略”。

在技术实现上，这套流程必须接入现有 `PhysicsEngine` / `NavigationEngine` / `state_batch` 架构，并保持上层协议不被破坏。现有方案已经明确要求 `NavigationState`、`state_batch` 和 Godot 渲染契约保持不变，物理层替换不能导致上层算法全部重写。

***

# 二、总体流程

建议将导丝过弯设计成一个 6 步引导流程：

```text
Step 1 术前塑形：选择/设计导丝头端形状
Step 2 旋转定向：让头端弯曲面朝向目标分支
Step 3 支撑建立：导管/sheath 跟进，建立近端支撑
Step 4 小步试探：推—停—看—回撤—再旋转—再推
Step 5 贴壁滑入：软头沿壁滑入目标腔道
Step 6 策略切换：失败后换 tip、换导管、换路径或回退
```

对应系统状态机：

```text
PREOP_SHAPE_PLAN
    ↓
TIP_ORIENTATION
    ↓
SUPPORT_READY
    ↓
MICRO_ADVANCE
    ↓
WALL_SLIDE
    ↓
PASS_TURN_SUCCESS

任一步失败：
    ↓
STALL_OR_RISK_DETECTED
    ↓
STRATEGY_SWITCH
    ↓
重新进入 TIP_ORIENTATION / SUPPORT_READY / MICRO_ADVANCE
```

# 三、Step 1：先把导丝头端做成“会转弯的形状”

## 3.1 临床含义

医生会根据术前影像和血管走形，把导丝远端塑成小弯、C 形、S 形、Angled、Hook、J-tip 等形状。目的不是让整根导丝硬弯，而是让头端的小弯能在分叉或急弯处“找入口”。

## 3.2 系统中的流程引导

### 术前界面：Tip Shape Planner

用户进入病例后，系统先展示目标路径和关键弯道：

```text
[病例加载]
    ↓
[选择目标分支]
    ↓
[系统标注关键弯道]
    ↓
[推荐 tip 形状]
    ↓
[用户确认/调整]
```

界面显示：

| 区域        | 内容                                      |
| :-------- | :-------------------------------------- |
| 左侧 3D 血管  | 显示主路径、分叉、急弯段                            |
| 右侧 Tip 面板 | 选择 Straight / Angled / J / C / S / Hook |
| 底部风险提示    | 最大曲率、分支夹角、推荐 tip 半径                     |
| 预览窗口      | 显示导丝头端形状与目标分支入口关系                       |

### 推荐规则

```python
if branch_angle < 30deg:
    recommend = "small angled tip"
elif branch_angle < 70deg:
    recommend = "J-tip or C-shape"
else:
    recommend = "Hook / larger curve + catheter support"
```

### 数据结构

```python
TipShapeProfile:
    shape_type: str              # straight, angled, J, C, S, hook
    curve_radius_mm: float
    curve_angle_deg: float
    tip_length_mm: float
    soft_tip_length_mm: float
    tip_stiffness: float
    preferred_branch_angle: tuple
```

### WebSocket / 配置消息

```json
{
  "type": "device_config",
  "guidewire": {
    "tip_shape": "J",
    "tip_curve_angle_deg": 45,
    "tip_length_mm": 8,
    "soft_tip_length_mm": 15,
    "tip_stiffness": 0.25
  }
}
```

## 3.3 物理层体现

在 Newton/VBD 物理中，不能只在渲染层画一个弯头，而要让远端 body 初始几何和刚度真的不同：

```text
proximal hard body
    ↓
transition segment
    ↓
soft distal tip with pre-shaped curvature
```

实现点：

1. `NewtonEngine` 初始化导丝时，远端若干 body 按 tip curve 预置；
2. tip 段弯曲刚度低于 body 段；
3. tip 段接触风险阈值更敏感；
4. tip shape 进入 `RawPose` / debug 状态，便于训练回放。

## 3.4 HUD 引导语

```text
步骤 1/6：头端塑形
当前弯道角度：62°
推荐导丝头端：J-tip / C-shape
原因：目标分支入口角度较大，直头导丝容易顶壁。
```

# 四、Step 2：近端旋转，让头端朝向目标分支

## 4.1 临床含义

医生通过旋转体外近端导丝，让远端小弯朝向目标分支。过弯时常见操作不是持续推进，而是：

```text
旋转定向 → 轻推试探 → 不对就回撤一点 → 再旋转 → 再轻推
```

## 4.2 系统中的流程引导

### 术中界面：Tip Orientation Guide

进入弯道前，系统切换到“头端定向”引导：

```text
[导丝接近分叉/急弯]
    ↓
[系统显示目标方向扇区]
    ↓
[用户旋转导丝]
    ↓
[tip 朝向进入绿色扇区]
    ↓
[允许轻推试探]
```

界面元素：

| 元素       | 作用            |
| :------- | :------------ |
| 目标方向箭头   | 指向目标分支入口      |
| tip 朝向箭头 | 显示当前导丝头端弯曲方向  |
| 旋转角度环    | 显示近端输入角度      |
| 远端响应角    | 显示远端实际 tip 角度 |
| 扭转滞后条    | 显示近端旋转与远端响应差异 |

## 4.3 物理层体现

当前技术方案中，后续 D4 已经明确要把 `rotate` 真正转化为扭转传导，而不是只做视觉旋转。D4 的目标包括 Cosserat 扭转约束、软头硬身分段刚度和导管/sheath 约束。

需要新增：

```python
TwistState:
    proximal_rotation_deg: float
    distal_tip_rotation_deg: float
    torsion_lag_deg: float
    torsion_energy: float
    tip_facing_score: float
```

### tip 朝向评分

```python
tip_facing_score = dot(tip_curve_normal, target_branch_direction)
```

评分解释：

| 分数      | 状态                 |
| :------ | :----------------- |
| > 0.8   | 朝向正确，允许推进          |
| 0.4–0.8 | 可试探，但建议微推          |
| < 0.4   | 不建议推进，应继续旋转        |
| < 0     | 明显背离目标，推进可能误入分支或顶壁 |

## 4.4 控制消息

```json
{
  "type": "control",
  "delta_push": 0.0,
  "delta_rotate": 0.15,
  "mode": "tip_orientation"
}
```

## 4.5 HUD 引导语

```text
步骤 2/6：旋转定向
请旋转导丝，使红色 tip 朝向绿色目标扇区。
当前远端响应滞后：18°
建议：停止推进，仅小幅旋转。
```

# 五、Step 3：用微导管 / 导管 / 鞘管提供支撑

## 5.1 临床含义

如果只推一根很软的导丝，力量容易在弯道里耗散，导丝会屈曲、顶壁、回弹或进入错误分支。临床上会用微导管、导管、鞘管形成同轴支撑系统。

导丝先探路，导管再沿导丝跟进，支撑点不断前移。

## 5.2 系统中的流程引导

### 术中界面：Support Builder

当系统检测到以下情况时，提示建立支撑：

- slack 增大；
- tip 前进慢；
- root 运动明显大于 tip；
- 接触力升高；
- 弯道曲率大；
- 分叉角度大。

流程：

```text
[tip 到达弯前]
    ↓
[系统检测需要支撑]
    ↓
[提示推进微导管/导管]
    ↓
[支撑点前移]
    ↓
[自由导丝长度变短]
    ↓
[允许继续微推]
```

## 5.3 物理层体现

已有方案已经确认 root 直接驱动会导致红色 tip 卡住、root 先动，根本原因包括缺少 sheath/导管约束和导丝受压屈曲。

因此需要把导管/sheath 从“视觉对象”升级为“物理约束对象”。

### 新增对象

```python
CatheterState:
    catheter_tip_arclen: float
    sheath_tip_arclen: float
    supported_body_indices: list[int]
    free_wire_length_mm: float
    support_strength: float
    catheter_following_error_mm: float
```

### 物理约束

```text
sheath/catheter 内部导丝段：
    lateral motion constrained
    bending amplitude limited
    friction enabled
    axial sliding allowed

导管外自由段：
    full physics
    can bend / contact / slide / buckle
```

### 控制消息

```json
{
  "type": "control",
  "catheter_advance": 0.2,
  "sheath_advance": 0.0,
  "delta_push": 0.0,
  "delta_rotate": 0.0
}
```

## 5.4 风险指标

| 指标                      | 含义                 |
| :---------------------- | :----------------- |
| `free_wire_length_mm`   | 导管外自由导丝长度          |
| `slack_mm`              | 已喂入长度与 tip 实际前进差   |
| `support_ratio`         | 被导管/sheath 支撑的导丝比例 |
| `buckling_risk`         | 屈曲风险               |
| `catheter_follow_error` | 导管是否跟不上导丝          |

已有 anti-buckle 方案已经引入 slack budget 和 sheath 自动模式，用于减少自由段柱屈曲和盘绕。

## 5.5 HUD 引导语

```text
步骤 3/6：建立导管支撑
检测到 slack = 10.8mm，tip 前进不足。
建议：推进微导管 3–5mm，缩短无支撑导丝长度。
```

# 六、Step 4：小步推拉，而不是持续硬推

## 6.1 临床含义

真实操作不是持续硬推，而是：

```text
微推 → 停止 → 观察 tip 反应 → 必要时回撤 → 旋转 → 再微推
```

如果遇到阻力或影像提示异常，不应继续增加推力。

## 6.2 系统中的流程引导

### 术中界面：Micro Advance Coach

进入大弯或分叉后，系统不再鼓励用户长按推进，而是将推进动作拆成小节拍：

```text
1. Rotate
2. Micro Push
3. Hold
4. Observe
5. Pullback if needed
6. Re-orient
7. Micro Push again
```

每个节拍都有时间窗：

| 动作   | 建议持续      |
| :--- | :-------- |
| 微推   | 0.1–0.3 秒 |
| 停止观察 | 0.2–0.5 秒 |
| 小幅回撤 | 0.1–0.2 秒 |
| 旋转调整 | 0.2–0.5 秒 |

## 6.3 控制层实现

新增 `MicroMotionController`：

```python
class MicroMotionController:
    def update(input, state):
        if state.risk.high_contact:
            return Control(push=0, pull=0.2, rotate=0)
        if state.tip_facing_score < 0.5:
            return Control(push=0, rotate=suggest_rotate(), pull=0)
        if state.stall_detected:
            return Control(push=0, pull=0.1, rotate=scan())
        return Control(push=micro_push(), rotate=small_rotate(), pull=0)
```

## 6.4 训练评分

系统应记录用户是否“持续硬推”。

新增指标：

```python
hard_push_duration_sec
continuous_push_distance_mm
push_without_tip_motion_mm
push_during_high_contact_count
micro_push_ratio
pullback_retry_count
```

评分规则：

| 行为                   | 评分   |
| :------------------- | :--- |
| 小步推拉，tip 稳定前进        | 加分   |
| 接触力升高后停止推进           | 加分   |
| tip 停滞仍持续硬推          | 扣分   |
| breach warning 后继续推进 | 严重扣分 |
| 合理回撤再旋转              | 加分   |

## 6.5 HUD 引导语

```text
步骤 4/6：小步试探
请轻推 1–2mm 后暂停观察。
当前 tip 未同步前进，禁止持续硬推。
建议：回撤 0.5mm，顺时针旋转 10° 后再试。
```

# 七、Step 5：让软头“贴壁滑入”，避免尖端顶壁

## 7.1 临床含义

大弯处最危险的是导丝尖端直接顶住外侧壁。医生希望柔软、圆滑或预弯的 tip 沿壁滑动进入目标方向，而不是像针一样顶壁。

## 7.2 系统中的流程引导

### 术中界面：Wall-Slide Guidance

当 tip 接近大曲率外侧壁时，系统显示：

- tip 与壁面的距离；
- 接触点；
- 接触力；
- tip 与壁面切线夹角；
- 是否属于“贴壁滑行”还是“尖端顶壁”。

## 7.3 风险判断

核心区分：

```text
贴壁滑入：tip 与壁面切线方向接近，接触力低，tip 仍沿腔道前进
尖端顶壁：tip 指向壁面法线方向，接触力升高，tip progress 停滞
```

新增指标：

```python
WallContactState:
    contact_force: float
    wall_distance: float
    breach_mm: float
    tip_wall_angle_deg: float
    tangential_slide_score: float
    normal_poking_score: float
```

### 判断逻辑

```python
if contact_force < safe_force and tangential_slide_score > 0.7:
    status = "WALL_SLIDE_OK"

elif normal_poking_score > 0.7 and tip_progress_delta < threshold:
    status = "TIP_POKING_WARNING"

elif breach_mm > 0.3:
    status = "BREACH_STOP"
```

现有方案已经意识到 force 模式下不能简单用 `wall_distance` 判定危险，因为正常贴壁不等于穿壁，后续已改为按穿透量和接触刚度来判断。

## 7.4 物理层体现

需要：

1. tip 段低刚度；
2. tip 端部圆滑接触；
3. friction / damping 可调；
4. 接触力进入 `RawPose`；
5. breach 作为真实停止条件；
6. tip 方向与壁面法线夹角用于风险评估。

## 7.5 HUD 引导语

```text
步骤 5/6：贴壁滑入
当前状态：低力贴壁滑行
接触力：安全
tip 与壁面夹角：18°
建议：保持微推，不要增加推力。
```

危险时：

```text
警告：tip 正在顶壁
tip 前进停止，但 root 仍在推进。
请停止推进，回撤 0.5–1mm 后重新旋转定向。
```

# 八、Step 6：如果过不去，就换策略，而不是加大推力

## 8.1 临床含义

如果导丝过不去，临床上不会一味加大推力，而是换策略：

- 换 tip 形状；
- 重新塑形；
- 换更软或更支撑的导丝；
- 换微导管；
- 增加近端支撑；
- 改变透视角度；
- 改变进入路径。

## 8.2 系统中的流程引导

### 失败检测

系统进入 `STRATEGY_SWITCH` 的条件：

```python
if stall_steps > N:
    trigger_strategy_switch()

if contact_force > high_force_threshold:
    trigger_strategy_switch()

if slack_mm > max_slack:
    trigger_strategy_switch()

if wrong_branch_score > threshold:
    trigger_strategy_switch()

if repeated_micro_push_failed:
    trigger_strategy_switch()
```

### Strategy Switch 面板

进入失败策略面板后，系统不允许继续单纯加大 push，而是给出选项：

| 失败原因     | 推荐策略                |
| :------- | :------------------ |
| tip 朝向错误 | 回撤 + 重新旋转           |
| tip 顶壁   | 换更软 tip / 减小推进 / 回撤 |
| 导丝屈曲     | 推进导管支撑 / 缩短自由段      |
| 误入分支     | 回撤到分叉前 / 重新定向       |
| 弯道角度太大   | 换 C/J/Hook tip      |
| 支撑不足     | 换更强支撑导管 / sheath 前移 |
| 宽腔甩动     | 降低推进增益 / 增加导管约束     |
| 路径不可达    | 改变 route / 选择备用路径   |

## 8.3 策略切换数据结构

```python
StrategyOption:
    option_id: str
    label: str
    reason: str
    expected_effect: str
    risk: str
    required_action: dict
```

示例：

```json
{
  "option_id": "change_tip_to_J",
  "label": "更换为 J-tip",
  "reason": "目标分支入口角度较大，当前 angled tip 多次顶壁",
  "expected_effect": "提高分支入口选择能力",
  "risk": "可能增加宽腔内甩动",
  "required_action": {
    "device_change": {
      "tip_shape": "J",
      "tip_curve_angle_deg": 60
    }
  }
}
```

## 8.4 HUD 引导语

```text
步骤 6/6：策略切换
连续 3 次微推失败，tip 未进入目标分支。
禁止继续增加推力。

推荐策略：
1. 回撤 1mm，顺时针旋转 20°
2. 推进微导管 3mm 增加支撑
3. 若仍失败，切换为 J-tip
```

# 十六、总结

这 6 条临床经验在技术方案中应具体体现为：

1. **导丝头端塑形** → Tip Shape Planner + 远端软头几何/刚度建模；
2. **近端旋转定向** → tip 朝向评分 + 扭转传导 + 目标扇区 HUD；
3. **导管系统支撑** → catheter/sheath 物理约束 + 支撑点前移；
4. **小步推拉** → MicroMotionController + 硬推检测 + 回撤重试；
5. **软头贴壁滑入** → 贴壁/顶壁区分 + 接触力/穿透量风险判断；
6. **失败后换策略** → Strategy Switch 面板 + 换 tip/换导管/换路径/回撤重试。

最终用户看到的不是一套抽象参数，而是一条类似临床训练教练的流程：

```text
先选合适的头端形状
→ 旋转让头端对准入口
→ 推进导管建立支撑
→ 小步推拉试探
→ 让软头贴壁滑入
→ 失败时回撤并换策略
```

这套流程能把“临床经验”变成“可操作、可评估、可回放、可训练”的仿真系统。
